## Overview

Open Agent Memory 0.2.0 pairs an updated BEAM-10M evaluation with scheduled and on-demand Profiles, Insights that combine related facts across sources, and more control over recall.

## Changes

- **Updated BEAM-10M evaluation.** Across 200 questions from ten conversations at the 10-million-token scale, OAM earned **78.23% mean rubric credit** versus Hindsight's published **64.08%**. OAM passed **172/200** questions versus **147/200**, using **24,676.88** mean saved context tokens versus **27,373.25**, a **9.85% reduction**. OAM used MiniMax M3.1 Flash adaptive for answering and judging. Both runs use the same questions, references, rubrics, scoring rules and archived prompt templates. Three OAM judge calls added a JSON example to the provider wrapper while keeping the archived judge text and scoring rules. The answer models, judge models and memory pipelines differ. The OAM score combines 180 current recalls and 20 previously saved contexts. [Method and results](../benchmarks.md#3-beam-10m) · [Pinned per-question evidence](https://github.com/rocke2020/open-agent-memory-benchmark/tree/b24c8037adcb97666be63944841b7581d50141bf/eval_results/beam10m-20261119)
- **LongMemEval S.** The v0.1.0 milestone remains **95.2% (476/500)** versus Hindsight's recorded **94.6% (473/500)**. OAM averaged **11,373.58** saved context tokens across 497 measured contexts versus Hindsight's **43,124.55** across 500, a **73.63% reduction**. [Settings and denominator](../benchmarks.md#1-latest-longmemeval-s-476500-at-18k)
- **Personal and custom Profiles.** Configure UTC cron schedules, an independent full-refresh schedule, or refresh after consolidation settles. Automatic triggers default off. The existing Create/Refresh path prepares unfinished inputs before generating. Use `POST /v1/users/{user_id}/profile/generate` to create a cited, instruction-specific Profile on demand. The API returns it without storing the instruction or generated body. [Profile guide](../profiles.md)
- **Insight consolidation across sources.** Ready sources for one user and index generation share a fixed window, anchored by the first ready source and set to 24 hours by default. A synthesis can combine related facts from several members, with separate readiness and generation-budget accounting per source. Existing source-owned jobs, removal repairs and explicit backfills continue to work. [Insight design](../indexing-retrieval.md#4-insight-consolidation)
- **Recall presets and personal evidence.** Override supported fast and normal settings per request. Separate temporal traversal limits from final result counts. Improved per-term lexical recall and an opt-in personal-evidence channel help surface original user passages supporting current preferences and experiences. [Recall configuration](../../configs/README.md#7-temporal-traversal-budgets-and-request-overrides)
- **Memory Inspector.** See the latest update time for the selected collection. Create and refresh the stored Profile in Inspector. Manage structured Profile Data through the HTTP API. [Inspector guide](../memory-web-ui.md)
- **DSH exact memory removal.** The independently published DSH 0.0.2 package adds `memory_remove` for an exact memory or Insight ID on explicit user request. [DSH integration](../../integrations/dsh/README.md#memory-removal)

OpenClaw and DSH are independently versioned at 0.0.2. MCP is at 0.0.1.

## Verification and publication

The benchmark results come from the recorded evaluation revisions and configurations in the linked evidence. The [GitHub Release](https://github.com/rocke2020/open-agent-memory/releases/tag/v0.2.0) carries artifact checksums and publication verification.

The default pytest suite passed 2,060 cases and skipped 668 optional cases. The isolated PostgreSQL suite verified 664 distinct cases across the initial run and a focused rerun, with two skips. The rerun resolved fixture preconditions by migrating the shared test database and supplying authentication for reconnections. Ruff lint, Ruff formatting and Mypy passed. The OpenClaw, MCP and DSH suites passed 67, 28 and 18 tests, respectively. The three selected npm archives match the corresponding local runtime, package metadata and license files.

The wheel and source distribution built successfully. Both Linux images reported v0.2.0 and matched 184 packaged source, configuration and migration files. ARM64 ran natively. AMD64 CLI and package checks ran under emulation.

A synthetic HTTP provider and an isolated PostgreSQL instance exercised the ARM64 upgrade from v0.1.0. Migrations 0038 and 0039 preserved a cited Profile revision and existing recall evidence. The upgraded worker completed a queued source-owned Insight job. The custom Profile endpoint returned cited content with `Cache-Control: no-store` and preserved the stored Profile. Two new sources joined one Insight window whose completion triggered an automatic full Profile refresh. Inspector HTML and three required assets returned HTTP 200. This probe covers the synthetic upgrade path. See the GitHub Release evidence for provider and public-download checks.

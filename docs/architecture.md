# Open Agent Memory Architecture

## Overview

OAM is one governed data plane: immutable source evidence is authoritative, memories and Profiles are rebuildable projections, and recall assembles bounded context without generating an answer. PostgreSQL owns content, policy, work, and application-replica recovery so API and worker processes can be replaced without losing accepted inputs. The user-qualified retain/recall core, source lifecycle, recorded inspection and portable export and the deterministic Profile path have functional verification; live Profile model quality, deployment recovery and benchmark performance remain separate gates.

## 1. Authority and Isolation

A tenant is the organization security boundary. Each `(tenant_id, user_id)` identifies one personal memory collection. The configured authentication mode resolves that pair before content access: `api_key` derives it from a user key, `trusted` accepts a validated upstream assertion, and loopback-only `dev` accepts a local assertion with no privacy boundary. A root key cannot select personal content in `api_key` mode; a trusted upstream with the root key can assert a user in nonlocal `trusted` mode. Every content identity, support link, operation, attempt, trace and idempotency key belongs to that pair; the public contract has no third collection selector. [Mode admission](../src/oam/api/app.py), [request identity](../src/oam/auth/modes.py) and [database authority](../src/oam/api/runtime.py) are the implemented path.

PostgreSQL row-level security is a mandatory second boundary behind explicit SQL predicates. Migration credentials are separate from non-owner, non-superuser, non-`BYPASSRLS` API and worker roles. A worker claims metadata through a narrow queue role, then binds the authorized tenant/user pair in a separate content transaction. [The user-identity migration](../migrations/0004_user_identity.sql) preserves existing personal collections while renaming their keys and policies; [the key-authority migration](../migrations/0005_personal_key_authority.sql) makes old administrator or cross-user grants ineffective and backfills owner principals without deleting content. [The asserted-user migration](../migrations/0006_asserted_user.sql) registers a first-seen user only within an active tenant and keeps automatic rootless mode selection stable across restarts. [Transaction context](../src/oam/db/context.py) binds `oam.user_id`. Administrator `POST /v1/users` creates a collection and first user key without a creator content grant.

The operator runs migration before starting application replicas. Rootless setup initializes the `default` tenant without a credential; keyed setup creates an administrator and stores only the root-secret digest. A generated secret is handed to a new operator-only file, while an operator-supplied secret is already known to the operator. Interrupted generated-secret handoff requires explicit recovery for that same administrator. Runtime credential administration verifies the actor from the supplied secret digest, issues a separate sibling key for rotation, and revokes only same-tenant credentials. API processes never receive migration credentials. [Bootstrap](../src/oam/auth/bootstrap.py), [authentication](../src/oam/auth/repository.py), and [HTTP composition](../src/oam/api/runtime.py) own these boundaries.

The [configuration loader](../src/oam/config.py) validates canonical YAML, overlays an explicitly selected partial operator configuration, and freezes the resolved values. [HTTP admission](../src/oam/api/admission.py) uses those same values for request limits and capabilities; request schemas enforce structure without supplying a second set of numeric limits. Full-release readiness remains false while later product gates remain unimplemented.

## 2. Evidence, Projections, and Resources

Eligible interactions enter L0 and may produce L1. Related L1 records may produce supported L2 Insights with one descriptive subtype: `preferences`, `patterns`, `projects`, `relationships`, `experiences` or `general_insights`. These labels share the same synthesis/support pipeline and do not affect identity or ranking. Fact, Insight and Profile generation refer to the individual subject as "the user" without inferring gender; exact source quotes remain unchanged. An explicit Profile refresh advances eligible delayed L2 work, waits for it to settle, then freezes eligible L1/L2 and Profile Resource versions before publishing L3. Evidence Resources instead produce detailed passages and a derived abstract; neither output is an input to L1, L2, or L3.

```text
eligible interactions -> L0 -> L1 -> supported L2 --+
eligible L0 detail ----------------------------------+-> requested L3
explicit Profile Resources --------------------------+

text/HTML/PDF/image upload or HTTPS URL -> immutable original -> passages + abstract -> joint recall
Evidence Resource ----------------------------------------------X-> L1/L2/L3
```

Every generated claim retains support to immutable source versions and locators. Source revision or deletion changes eligibility before a response or worker publication can use the old derivative.

The [Resource parsers](../src/oam/resources/) retain native PDF page text, render scanned pages and text pages with a large image or vector table for [visual extraction](../src/oam/workers/index_source.py), and cite physical PDF pages or image regions when known. Text fact extraction and visual document extraction use the same `extraction` model binding, which must support both chat and vision. The [model adapter](../src/oam/models/runtime.py) sends bounded image bytes to that binding; [indexing](../src/oam/indexing/store.py) counts its measured usage. Detailed text passages enter the existing embedding and lexical indexes; image pixels do not become search vectors. The `embedding` role selects a separate binding, while `index.embedding_dimensions` remains the sole configured vector-size owner for runtime validation and database initialization. A failed later PDF page leaves completed passages marked as partial, and a failed abstract does not erase detailed passages.

The [PDF child boundary](../src/oam/resources/pdf_isolated.py) runs local parsing, page inspection and rendering outside the durable worker with a parent-enforced timeout and bounded transfer. The worker keeps model calls and publication in its own process; a child crash or timeout produces a Resource failure without an in-process parse retry.

The [HTTPS Evidence fetcher](../src/oam/resources/url_fetch.py) accepts a caller-declared HTML/PDF/PNG/JPEG type only after the retain caller is authorized. It resolves a public address, connects to that checked address with TLS hostname verification, refuses redirects and compression, and stores the bounded returned bytes as the immutable original. A committed identical URL request reuses its receipt without another fetch. URL query data is excluded from stored display provenance and public errors; workers parse the stored bytes and never revisit the URL.

An L1 memory unit is one concise, independently addressable fact sentence with a stable `memory_id`; raw passages and L2 Insights remain distinct kinds. [HTTP admission](../src/oam/api/app.py) and [runtime composition](../src/oam/api/runtime.py) accept `/v1/retain` JSON interactions and `/v1/users/{user_id}/resources` tagged Evidence text, URL, file or structured Profile originals. Public callers never manage source/message IDs or revision numbers on retain; Evidence `PUT` and Profile Resource revision through `POST` supply `If-Match`, while [source storage](../src/oam/db/sources.py) assigns the next immutable revision. The [indexing worker](../src/oam/workers/index_source.py) validates exact caller annotation spans and publishes caller clocks/times on passages and supported facts. Missing extraction does not erase caller-annotated raw evidence. Source deletion is available; removal of one generated fact remains a later separate control.

[L1 extraction](../src/oam/indexing/extraction.py) keeps explicit personal facts, preferences, experiences, plans, goals, decisions, constraints and meaningful secondary context. Assistant conclusions, consequential recommendations and performed actions qualify when useful and grounded; generic exposition, illustrative examples and advice inventories without specific ongoing context are omitted. All eligible original passages remain in L0. Compact model output omits empty arrays and the default fact category while retaining supported preference/experience categories, named entities, relations and date annotations. Singleton calls omit passage identifiers and validate against their one offered center. Grouped calls use short call-local passage identifiers; [validation](../src/oam/indexing/grouping.py) checks each exact quote against its offered owner before restoring the canonical passage identifier for checkpointing and publication. Missing or foreign owners are rejected, and recursive split calls rebuild their own identifier mappings. Each fact quote is one contiguous original substring; time-annotation quotes resolve within that accepted support span, so repeated dates elsewhere in the passage do not invalidate it. An explicit exact occurrence outside the fact, ambiguous occurrences within its support and invalid temporal meanings remain rejected. The [indexing recipe](../src/oam/indexing/identity.py) changes with this extraction contract, preventing reuse of prior extraction checkpoints.

Quote validation first uses exact original text; when a quote omits supported paired `**` emphasis delimiters in prose, a unique character-preserving match maps back to the exact original substring and source offsets before publication. Formatting recovery is limited to source-start chunks, where preceding code-block context is not missing. Code, uncertain markup, rewritten text and ambiguous matches retain strict rejection. Temporal quotes use the same mapping only within accepted fact support; valid explicit spans outside it are rejected.

The [chunker](../src/oam/indexing/chunker.py) uses `chunk.ingestion` to split each message or document into exclusive source passages before either singleton or grouped extraction. The separate `chunk.recall` settings belong to the reserved `include.chunks` response option, which is not yet served. [Indexing identity](../src/oam/indexing/identity.py) includes ingestion chunk settings and excludes recall budgets; [capabilities](../src/oam/api/app.py) publish both under the single `limits.chunk` section.

The [source worker](../src/oam/workers/index_source.py) submits individual extraction groups through a sliding window. Each source runs at most `provider.llm_concurrency` extraction tasks and retains at most twice that many outstanding groups. References freeze before dispatch and exclude the current source. Successful outputs [checkpoint](../src/oam/indexing/store.py) as they complete; the source thread embeds and publishes a ready prefix in source order while later extraction continues. Each group's fact embeddings have a stable checkpoint identity, so completion timing cannot change checkpoint membership on retry. An earlier unfinished group still delays publication of later groups, but the pipeline does not wait for a complete extraction wave before consuming ready facts. On error it cancels queued tasks and drains running tasks before recording failure; retries reuse completed checkpoints. The source orchestration keeps the attempt unresolved throughout overlapping extraction and embedding, so a sibling's successful checkpoint cannot hide an unknown outcome. Guarded checkpoint commits and local stage tracking settle it only after all outstanding stages finish and their outputs are saved. If several stages fail with unsaved outcomes, the attempt remains unresolved, usage stays partial and automatic retry stops; single-stage known failures retain their existing retry rules. Readiness and link publication follow the final drain. Source leases renew at stage dispatch and split-retry boundaries; configure the lease to cover the attempt timeout and persistence margin.

Independent source operations run concurrently through the existing durable queue and [worker runner](../src/oam/workers/runner.py), bounded by `worker.max_tasks` and `user.concurrency`. A client processing a batch can submit a bounded window of independent sources before waiting for completion; it retains every receipt and waits for every operation's required readiness flags before consuming the completed batch. Admission order does not imply completion order, and available cross-source reference facts can differ from serial submission. The [model runtime](../src/oam/models/runtime.py) gives generation and embedding separate budgets; deployment-wide PostgreSQL permits cap them independently. [Indexing transactions](../src/oam/indexing/store.py) acquire separate transaction advisory slots defined by [migration 0024](../migrations/0024_indexing_db_admission.sql), bounded across replicas by `database.indexing_concurrency`. Local admission limits connection creation before waiting for those shared slots. Commit, rollback and connection loss release the DB slots, and remote model calls hold none. Each source retains its own originals, version, claim, fence and checkpoints.

The [group planner](../src/oam/indexing/grouping.py) combines adjacent eligible passages from one source into a bounded L1 call by default. It fixes group membership before embedding/concurrency batches, breaks at eligibility gaps, and keeps complete passage text, individual roles, message timestamps and exact source offsets. Group size respects the serialized input bound, passage/fact cap and a conservative output estimate (three times source-text tokens plus 128 tokens per passage), bounded separately by `extraction.group_max_estimated_output_tokens: 4096`; this estimate cannot guarantee model coverage. Extraction and Insight generation use `extraction.max_output_tokens: 64000` as the actual model completion cap; Resource vision and abstracts use `resource.max_output_tokens: 4096`, leaving room for reasoning and visible JSON. Length-terminated output raises a typed overflow error. Indexing then recursively halves a group at passage boundaries, or splits a singleton source span near a sentence boundary while preserving exact offsets and passage ownership. Split results merge in source order with remapped fact relations and cumulative usage, including overflow attempts. A source span of at most 500 non-surrounding-whitespace characters, or a span that cannot form two nonempty halves, fails rather than being dropped. Each split child rechecks cancellation and source eligibility and renews its fenced lease before dispatch, with no transaction held during the model call. Branches share the existing outer checkpoint; a completed merged extraction is reused on retry, while an interrupted or failed split tree may repeat its successful branches. Oversized groups split at passage boundaries, and a singleton uses the original extraction protocol. Each grouped fact names its owning passage; validation checks that passage alone. The worker publishes a whole group and its cross-passage relations in one fenced transaction, and retries reuse its completed checkpoint. `extraction.group_max_passages: 1` restores singleton grouping; the canonical value is 64. Grouping uses a distinct indexing generation, so existing collections require an explicit rebuild rather than automatic data replacement.

Existing-fact context is enabled by default with `extraction.reference_max_facts: 10` and a configurable `reference_max_input_tokens: 2048` estimated-token target; setting the fact limit to 0 disables it. [Reference selection](../src/oam/indexing/references.py) reuses passage embeddings to rank currently eligible L1 facts from other sources in the same tenant, user and generation, and freezes complete candidate text, identities, roles, mention dates and time qualifiers before extraction. [Wire packing](../src/oam/indexing/extraction.py) derives one proportional text preview per candidate using a shared scale after accounting for serialized metadata. The nearest complete sentence or comma-clause boundary may exceed the soft target; decimal numbers and numeric separators remain intact. Short and long texts use the same proportion, without short-first reservation or redistribution. Shortened text is marked `text_truncated: true` and treated as incomplete context whose omitted qualifiers and negation are unknown. Full stored facts and new source evidence remain unchanged. The complete model-input limit stays hard: admission retains a prefix of the relevance order and removes only whole reference records that cannot fit. Singleton/group calls and split retries derive views from full frozen candidates, avoiding repeated normalization. New facts still require current-source quotes, and distinct occurrences retain their own support. Optional existing relationship IDs are validated diagnostics, never support or directly published links. Completed extraction results are reused; unfinished calls remove references that became ineligible. Reference settings and the indexing recipe change generation, requiring an explicit rebuild for existing collections. Functional wiring does not establish a quality or latency gain; matched real evaluation remains required.

Resource revision and source deletion use distinct owner grants introduced by [source-control migration](../migrations/0009_source_controls.sql); [asserted-user grant migration](../migrations/0012_asserted_resource_grants.sql) gives new `dev` and `trusted` users those grants. The [follow-up migration](../migrations/0013_asserted_user_resource_grants.sql) upgrades existing asserted users that retain the original narrow grants, while preserving keyed-user and customized grants. Migration 0014 restricts the registration function owner and execution permissions. Revision commits a new current version and advances the user's policy epoch, excluding the previous version before reindexing. Deletion commits all-version exclusion, cancels outstanding source work and returns a separate cleanup operation in one transaction. [Eligibility SQL](../src/oam/db/eligibility.py) requires every support of a derived L1/L2 version to remain current; [recall](../src/oam/retrieval/service.py) and [inspection](../src/oam/db/inspection.py) recheck the policy before returning content. [The cleanup worker](../src/oam/governance/cleanup.py) removes affected passages, facts, Insights, vectors, original bytes and server-held export parts under a fenced durable claim. Unrelated active sources stay eligible. Stored Profile reads validate current eligible inputs before returning supported fields.

Write admission follows mode-specific identity admission → shared HTTP/write capacity → bounded incoming bytes → JSON/multipart parsing and semantic limits → bound user and grant check → idempotency and intake capacity → atomic source/receipt acceptance. The [request middleware](../src/oam/api/admission.py) holds one PostgreSQL session admission slot through application execution and response completion; a rejected write consumes no total slot and its body is not read. Read routes, including POST search, can use the request slots reserved from writes. Any root-key verification transaction closes before waiting on the upload. Both write endpoints count actual received bytes against `api.max_request_bytes`, including chunked bodies; overflow stops parsing with `413` and closes partial upload files. This encoded-body cap is distinct from the accepted content/original limits and has one owner in [canonical configuration](../configs/oam.yaml).

[Fact-link construction](../src/oam/indexing/links.py) materializes only eligible new seeds. Direct indexing publishes temporal links, then atomically settles `index_source` and schedules one dependent `index_semantic_links` work unit under the same source operation, with a deterministic identity and immutable seed-manifest digest. Direct facts remain usable with `memory_ready=true`, `temporal_links_ready=true` and `links_ready=false`; operation status remains running (public HTTP status `processing`), and recall diagnostics remain pending. A zero-seed source completes immediately. The [semantic worker](../src/oam/workers/semantic_links.py) reads at most 1,000 seeds at a time in a separately bound, read-only transaction without the user-row lock or projection-epoch updates. Semantic neighbors query the persistent vector table in ascending cosine distance, making its existing HNSW index available to the planner. Current tenant/user, generation and source-support eligibility, self exclusion and prior-link capacity apply before the neighbor limit; positive weight and minimum similarity apply to the bounded result. The shared support predicate validates every support through exact passage, evidence, source-version and source primary-key lookups, avoiding repeated whole-user parent joins before planner statistics settle. Publication groups proposals by seed once and inserts retained edges in one bulk statement. Publication uses short [guarded transactions](../src/oam/indexing/store.py), rechecks both endpoints and the remaining per-seed cap, deduplicates edges and rechecks the lease before committing. Database statement timeouts bound semantic reads and writes; each batch renews the existing lease, and batches run sequentially within each claim. `index.semantic_link_ann_iterative_scan` and `index.semantic_link_ann_scan_max_tuples` own transaction-local index-time ANN tuning independently of recall settings. Approximate search may underfill or select different neighbors from exhaustive search; index existence alone does not prove physical index use or quality. Final guarded completion sets `links_ready=true`; retryable database failures reuse the same work unit, while terminal or [exhausted expired work](../migrations/0023_semantic_lease_settlement.sql) preserves direct memory and reports partial failure. Existing delayed Insight consolidation is scheduled at direct completion and retains its separate operation and readiness.

Temporal links retain exact gap, horizon and deterministic witness rules. Point-time construction returns at most the configured neighbor count before and after each seed timestamp, then selects the exact combined gap/ID top-k. Interval construction uses range overlap to find annotation pairs and selects one canonical best witness per target before applying the unit-neighbor cap. Intermediate projections carry only seed identity plus the applicable vector or timestamp, or annotation witness data. Publication remains inside the existing guarded transaction and requires complete link stages. The changed link recipe produces a new [index generation](../src/oam/indexing/identity.py); existing projections and queued work are not reassigned to it.

## 3. Durable Work

An accepted write commits its source/original bytes, idempotency identity, root operation, sealed stage manifest, and first runnable work units before returning `202`. Workers claim ready rows with short PostgreSQL transactions, leases, and monotonically increasing fences; remote model I/O happens outside the transaction.

[Intake accounting](../src/oam/db/queue_admission.py) counts unfinished logical root requests under the existing user lock. A delayed consolidation child retains its source root's slot, automatic retries retain the same slot, and an explicit retry creates a new admission. Exact idempotent reuse and unchanged Profile refresh require no new slot; deletion cleanup is exempt. The [claim function](../migrations/0018_profile_dependency_settlement.sql) serializes count-and-claim for a user and enforces two live claims across runners, skipping a capped user so other users can progress.

[Shared model admission](../src/oam/capacity.py) bounds generation at 32 calls and embeddings at eight across the deployment. Background indexing and foreground search share the eight embedding permits by default; `provider.embedding_search_reserved` optionally withholds permits from background work. Neither consumes a combined generation/embedding allowance. The [model client](../src/oam/models/runtime.py) commits dispatch intent before remote I/O, propagates its remaining deadline, and retains permits after uncertain transport outcomes. Known completion releases capacity independently of output validation. Operator [permit commands](../src/oam/models/permits.py) inspect and reconcile uncertainty, including foreground calls without a durable work operation; forced release remains explicitly unverified until remote completion is known. The [capacity migration](../migrations/0015_shared_capacity.sql) grants runtime roles only narrow metadata functions.

The [source repository](../src/oam/db/sources.py) takes the existing collection lock before checking request idempotency or allocating source/revision identities. A text document's `append` reads the current text, concatenates the exact supplied delta without separators and validates the completed size inside that same transaction, so concurrent appends cannot lose content. Documents use a stable `document_id`; Resource `PUT` requires `If-Match` and rechecks it at acceptance, while a matching idempotent retry reuses its prior receipt. File append is rejected. Source activation rejects deleted sources; ordinary original reads require an active current version. The [current claim function](../migrations/0016_queue_admission.sql) locks work rows without escalating queue privileges and withholds any unit with an unresolved external outcome until explicit [attempt reconciliation](../src/oam/operations/repository.py). The [indexing worker](../src/oam/workers/index_source.py) consumes accepted claims, persists compatible model-stage outputs and publishes supported representations. User-qualified operation routes expose readiness under the same grants. The [core acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) names the remaining proof.

Publication rechecks operation cancellation, lease/fence ownership, source version, learning eligibility and generation. Direct indexing of an independent active source may continue across another source's policy change; L2 consolidation also checks its frozen policy epoch because its input set can cross sources. A late or stale worker may preserve diagnostic attempt evidence but cannot publish canonical output. Retry reuses compatible completed work and creates a new attempt only for unfinished eligible stages.

A completed model response retains independently validated usage even when its generation is truncated/refused/empty or its embedding/scoring output is invalid. The [model adapter](../src/oam/models/runtime.py) carries that metering to the [existing attempt failure path](../src/oam/indexing/store.py); unavailable or malformed metering is never invented. Retryable extraction/Insight JSON/schema output uses the remaining durable claim budget: finalize the failed attempt and requeue its work atomically, then reuse completed stage checkpoints on the next claim. Model-adapter output rejection and input/output limits are not automatically retried merely because their usage is known. Network timeouts without a received response remain unresolved and are never automatically replayed. Successful-stage and known failed-attempt tokens are counted once each for the same source revision and generation; exhausted retries remain an explicit partial failure.

## 4. Retrieval and Profiles

The [recall service](../src/oam/retrieval/service.py) and [eligible SQL repository](../src/oam/retrieval/repository.py) implement one non-generative fast/mid/deep pipeline. An explicit ranking window wins; otherwise [deterministic query-time parsing](../src/oam/retrieval/query_time.py) resolves one event window from supported English/Chinese or bounded Japanese expressions. Ambiguous, invalid or unsupported implicit dates disable only the temporal arm and produce diagnostics, not request failure. FTS and narrow literal matches form one deduplicated lexical rank list under one shared cap and contribute one fusion vote per unit; temporal direct seeds use that same list. Fast fuses dense, lexical and optional temporal arms. Mid adds ordinary graph and optional temporal ranking, for at most four arms. Deep also runs L2 hierarchy, for at most five equally weighted arms. Ordinary graph and hierarchy retrieval remain free of date exclusion, while temporal spreading uses strict basis/window-qualified seeds, neighbors and path witnesses. Tenant/user, source and generation eligibility remain hard constraints everywhere; the [acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) still requires its full HTTP and evaluation matrix.

The [lexical recipe](../src/oam/retrieval/fts.py) routes English words to PostgreSQL `english`, numerals and pinned Jieba search terms to `simple`, and retains protected negation and time words. [HTML parsing](../src/oam/resources/html.py) preserves available title, heading and table caption fields for A/B/C ranking weights while passage text keeps D; other current sources supply D only. Recall combines distinct content terms with OR, retrieves a bounded ranked list per informative term, and preserves primary/full-match priority before each cap and final fusion. Configured `ts_rank_cd` field weights rank each term; recency breaks equal relevance before stable unit IDs. Exact-anchor results use the same bilingual representation to rank the remaining query words. The [schema migration](../migrations/0008_bilingual_fts.sql) adds a separate GIN-indexed bilingual vector and keeps the prior lexical vector available to older replicas; populated older generations require an explicit projection rebuild before this runtime can search them.

Fast uses its shorter deadline and caps temporal nodes at `min(search.temporal_nodes, search.fast.max_results)`, so pre-agent recall can follow temporal links; it skips ordinary graph, hierarchy and reranking. Mid and deep share entity/semantic links, two-hop outgoing causal paths and reranking when bound; deep alone traverses L2 parent/sibling paths. Both can still return L2 Insights through direct dense or lexical search. The canonical configuration gives mid's graph arm weight 0.1 and its other executed arms weight 1.0; deep gives its executed arms equal weight. Mid's [configured arm weights](../configs/oam.yaml) can be overridden together or separately. A hit found by both dense and graph receives both fusion votes and one final item with its path evidence. Initial [context admission](../src/oam/retrieval/service.py) starts from fused or configured reranker order, prioritizes the highest-ranked user-supported fact per source when available, and fills the remaining budget in rank order. A newly discovered related user fact and up to six additional passages near its cited turn use capacity remaining after query-ranked seeds and their original source windows are packed. Support-companion selection checks current fact eligibility before choosing one fact per passage; new companions follow the existing ranked seeds and passages in admission order, using remaining result and token capacity. The [graph activation](../src/oam/retrieval/algorithms.py) uses `n * n / (n * n + 1)` for `n` distinct shared entities, plus the strongest semantic and causal links, to order that arm. [Lexical retrieval](../src/oam/retrieval/repository.py) ranks eligible full-text matches for each distinct informative term under a per-term cap, combines those ranked lists into one bounded lexical arm, and uses strict full-text matching when filtering leaves no informative term. Exact quotes and numbered hyphenated identifiers use bounded literal matching; their remaining query words rank exact matches before the cap, while ordinary hyphenated words retain partial FTS. Without a reranker binding, mid and deep use fused results without degradation. All modes share citation hydration and incremental context packing under the versioned Unicode estimate, with configured source-seed caps of 36/36/56 for fast/mid/deep and a conservative 12,000 estimated-token request ceiling. The estimator is not an exact model-token bound; external evaluations independently count answer-visible context with their pinned tokenizer. Memory and Evidence compete under one result and estimated-token budget without origin quotas. The [core acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) functionally tests all three modes with Profiles disabled before L3 implementation.

After item and token admission, [shared context rendering](../src/oam/retrieval/context.py) associates facts with an already selected original passage only when all source/version/message/role identities and exact quoted character spans match. Returned items retain their relevance order, normalized fact text, complete citations, fact-owned time annotations and graph paths. The context presents one original passage followed by its related fact blocks, at the earliest member rank; `Source: [passage_id]` replaces repeated citations for those facts. Other chat citations use compact source revision, speaker, message ID and exact quote text; unfamiliar citation shapes keep their full JSON. Time fields remain visible, and facts with additional dates or graph paths keep their structured records intact. Insights, distinct source occurrences and facts without one fully covered selected passage retain standalone blocks. Grouping adds no model call or fetch; compact rendering may admit more ranked items under the same budget. The final context is recounted under the shared limit, and metadata keys have a stable order so [recorded replay](../src/oam/debug/traces.py) uses the same renderer.

Partial PDF page extraction requires explicit `allow_partial: true`; default recall rejects that incomplete Resource before returning context. The [Step 6 acceptance gate](acceptance.md#3-step-6-evidence-and-joint-recall-gate) verifies bilingual originals, physical-page citations, partial PDF behavior and combined Memory/Evidence context through public HTTP.

The [canonical configuration](../configs/oam.yaml) owns all three presets and deadlines. Public `POST /v1/recall` requires `user_id` and `query`, defaulting to mid when `recall_level` is omitted; the host selects fast explicitly before invoking the agent. Each pre-agent or ReAct recall gets its own operation budget, clamped by an explicit shorter caller deadline. Trusted shared-turn admission is an opt-in internal constraint, not a public body field. No automatic escalation occurs. Successful recall stores its bounded considered arms and final context under a trace ID after a final policy check; the [recorded trace reader](../src/oam/debug/traces.py) verifies every stored candidate against current eligibility before disclosing content.

[Batch and delegated recall](../src/oam/api/search.py) reuse the same [direct recall service](../src/oam/retrieval/service.py) through the [authorized HTTP runtime](../src/oam/api/runtime.py). Batch validates every caller query before dispatch, reserves deterministic shares of one request context budget, executes up to the configured query concurrency under one absolute deadline and returns input-ordered per-query outcomes. Delegated recall first makes at most one call through the configured [planner model role](../src/oam/models/runtime.py), validates its bounded query list, then runs those queries under the remaining deadline; a failed or invalid plan falls back to the original caller query when time remains. The [request contracts](../src/oam/contracts/search.py) keep mode and optional time controls common to both paths. Ordinary direct and batch recall remain non-generative.

The host runs fast recall before invoking the agent and supplies its evidence as initial context. During the ReAct loop, where the agent alternates reasoning and tool calls, it may request fast, mid, or deep again. OAM executes the selected preset; the agent owns subsequent queries, mode choices, and the final answer.

The [OpenClaw adapter](../integrations/openclaw/index.ts) binds one selected OpenClaw agent, defaulting to `main`, to one configured OAM user. Its owner-authorized local WebChat route covers that agent's conversational sessions, while external channels require an approved direct-conversation identity; the adapter recalls through OAM before an admitted turn and retains the completed human message after it. [Plugin setup and route limits](../integrations/openclaw/README.md) describe the operator-facing configuration.

The [Profile input loader](../src/oam/profiles/inputs.py) selects current interaction-backed L1 facts and L2 Insights with cited L0 passages, plus active structured Profile Resources; Evidence Resources and ineligible assistant text cannot support a Profile. Source event times let generated text qualify stated ages and past events. [Registered Resource mappings](../src/oam/profiles/resources.py) validate exact values before source activation. The [Profile service](../src/oam/profiles/service.py) compares eligible-input, canonical generation-prompt and saved-instruction identity without a model call: `GET /profile` validates supports against the collection's stored indexing generation and reads one stored content document, its references, last publication time and processing metadata; configured model or indexing-recipe changes do not prevent reading an eligible stored Profile. Refresh continues to require the configured generation; `POST /profile/refresh` returns `200` unchanged or a durable `202` receipt. It advances delayed L2 work for pending sources and waits for those jobs before generation. The bounded input selector reports how many eligible units did not reach generation; such a revision is not reported as fully current. The [canonical Profile prompt](../src/oam/profiles/prompt.txt) selects useful supports for a concise current portrait, replaces explicitly resolved corrections with the final state, preserves material unresolved qualifications and dated ages, and omits temporary test identifiers and incidental task details. Historical background and broad project activity are included only when useful, briefly. The [Profile worker](../src/oam/profiles/worker.py) generates one bounded text artifact in a JSON transport envelope, validates its cited support, appends exact Resource values and readable References to the default Markdown, deduplicates repeated default-format source references without changing their cited source, rejects unresolvable citation numbers, then rechecks inputs, lease and fence before publication. Successful Insight work for the active source version and generation establishes Profile input readiness, including a completed retry whose original receipt retains its failed diagnostics. A custom authorized instruction may request another text format, including JSON; the saved instruction participates in refresh identity, and a later instruction or reset cancels conflicting active Profile work. Cancellation fences publication; a completed attempt settles even after cancellation, so its instruction can be requested again, while uncertain external outcomes still require reconciliation. Withdrawal or supersession of cited support withholds the whole free-form snapshot until refresh, while a new eligible input leaves the prior eligible document available with a non-current machine status. L2 changes never generate L3 by themselves, and Evidence-only changes do not change Profile identity. [Request-scoped assembly](../src/oam/profiles/assembly.py) includes the complete stored document by default, omits it when `include_profile` is false or its full text exceeds the Profile budget, and never generates during recall. Older field-based revisions are rendered by the [document renderer](../src/oam/profiles/document.py) without regeneration or persistence: it preserves stored values, qualifiers, conflicts and all eligible references, and withholds the entire document if a support cannot be resolved. Profile reads and combined recall apply the complete-document budget and recheck source policy before returning content.

## 5. Inspection and Portable Export

Inspection reads only current eligible L1/L2 units and typed Resources. [Source inspection](../src/oam/db/inspection.py) lists active Evidence and Profile Resources, cited memories, current originals, Evidence abstracts or exact Profile mappings, and operation readiness under the user's read grant; the bundled [Inspector client](../src/oam/web/app.js) uses those public routes with no browser-side policy override. Source and generated text enter the page as text, credentials stay in page memory, and the API serves same-origin assets under CSP. The Inspector displays the one stored Profile document, safely formats parseable JSON, and submits explicit refresh instructions through the public route.

Recorded explain, output diff and read-only replay use [trace policy validation](../src/oam/debug/traces.py): an expired or withdrawn candidate cannot be revived by a trace. [Portable export](../src/oam/exports/repository.py) captures a format-1 manifest with current source identities, L0 evidence/passages, supported L1/L2 records and their links, Resource abstracts, eligible Profile content and reference metadata, and original descriptors. [Bounded JSONL parts](../migrations/0010_export_parts.sql) hold records without copying originals; original downloads recheck current source version, checksum and policy. Each committed indexing transaction advances the [projection epoch](../migrations/0011_projection_epoch.sql), so even a partial publication during running work invalidates an older export; source admission and policy changes also require a new export. The [offline validator](../src/oam/exports/validation.py) checks downloaded member paths, counts, lengths, hashes, source/original identity and support relationships. Downloaded copies are outside OAM's deletion control.

## 6. Runtime Topology

The [API lifespan](../src/oam/api/app.py) starts the [shared worker runner](../src/oam/workers/runner.py) by default, after configuration and database authority checks. Its dedicated thread pool executes synchronous processors without using HTTP handler threads. Dedicated deployments disable `worker.embedded_enabled` on APIs and launch `oam worker` separately; `--once` still claims at most one work unit. Each runner has up to `worker.max_tasks` task slots, ten by default, while deployment tooling selects process count. API and worker clients retain distinct database roles and foreground/background admission identities.

Shutdown first stops new claims and model dispatches, then waits up to `lease.shutdown_seconds`. Incomplete drain is reported; surviving synchronous tasks retain ownership of their clients until the final task exits. The service does not claim it can forcibly cancel an arbitrary Python thread. Readiness exposes embedded-runner health and unknown model-permit saturation while preserving the separate full-release readiness gate. PostgreSQL HA and abrupt process-loss certification remain separate release gates.

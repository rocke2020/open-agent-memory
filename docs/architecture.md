# Open Agent Memory Architecture

## Overview

OAM is one governed data plane: immutable source evidence is authoritative, memories and Profiles are rebuildable projections, and recall assembles bounded context without generating an answer. PostgreSQL owns content, policy, work, and application-replica recovery so API and worker processes can be replaced without losing accepted inputs. The user-qualified retain/recall core, source lifecycle, recorded inspection and portable export and the deterministic User Profile path have functional verification; live User Profile model quality, deployment recovery and benchmark performance remain separate gates.

## 1. Authority and Isolation

The [Memory Inspector](../src/oam/web/app.js) follows the same authenticated HTTP path as other clients: browse the mixed memory list or L2-only list → read the selected canonical typed ID → inspect source-supported entities and stored connections → open a related memory or supporting fact. [Detail assembly](../src/oam/db/inspection.py) delegates to [connection inspection](../src/oam/db/inspection_relationships.py), reusing current [entity witness eligibility](../src/oam/db/entity_eligibility.py) and checking source policy before returning the result. It never infers new entity or causal edges. The Retrieve view sends the user's complete query and chosen recall mode through `/v1/recall`, then renders its evidence list and context without generating an answer.

A tenant is the organization security boundary. Each `(tenant_id, user_id)` identifies one personal memory collection. The configured authentication mode resolves that pair before content access: `api_key` derives it from a user key, `trusted` accepts a validated upstream assertion, and loopback-only `dev` accepts a local assertion with no privacy boundary. A root key cannot select personal content in `api_key` mode; a trusted upstream with the root key can assert a user in nonlocal `trusted` mode. Every content identity, support link, operation, attempt, trace and idempotency key belongs to that pair; the public contract has no third collection selector. [Mode admission](../src/oam/api/app.py), [request identity](../src/oam/auth/modes.py) and [database authority](../src/oam/api/runtime.py) are the implemented path.

PostgreSQL row-level security is a mandatory second boundary behind explicit SQL predicates. Migration credentials are separate from non-owner, non-superuser, non-`BYPASSRLS` API and worker roles. A worker claims metadata through a narrow queue role, then binds the authorized tenant/user pair in a separate content transaction. [The user-identity migration](../migrations/0004_user_identity.sql) preserves existing personal collections while renaming their keys and policies; [the key-authority migration](../migrations/0005_personal_key_authority.sql) makes old administrator or cross-user grants ineffective and backfills owner principals without deleting content. [The asserted-user migration](../migrations/0006_asserted_user.sql) registers a first-seen user only within an active tenant and keeps automatic rootless mode selection stable across restarts. [Transaction context](../src/oam/db/context.py) binds `oam.user_id`. Administrator `POST /v1/users` creates a collection and first user key without a creator content grant.

The operator runs migration before starting application replicas. Rootless setup initializes the `default` tenant without a credential; keyed setup creates an administrator and stores only the root-secret digest. A generated secret is handed to a new operator-only file, while an operator-supplied secret is already known to the operator. Interrupted generated-secret handoff requires explicit recovery for that same administrator. Runtime credential administration verifies the actor from the supplied secret digest, issues a separate sibling key for rotation, and revokes only same-tenant credentials. API processes never receive migration credentials. [Bootstrap](../src/oam/auth/bootstrap.py), [authentication](../src/oam/auth/repository.py), and [HTTP composition](../src/oam/api/runtime.py) own these boundaries.

The [configuration loader](../src/oam/config.py) validates canonical YAML, overlays an explicitly selected partial operator configuration, and freezes the resolved values. [HTTP admission](../src/oam/api/admission.py) uses those same values for request limits and capabilities; request schemas enforce structure without supplying a second set of numeric limits. Full-release readiness remains false while later product gates remain unimplemented.

## 2. Evidence, Projections, and Resources

Eligible interactions enter L0 and may produce L1. Related L1 records may produce supported L2 Insights with one descriptive subtype: `preferences`, `patterns`, `projects`, `relationships`, `experiences` or `general_insights`. These labels share the same synthesis/support pipeline and do not affect identity or ranking. Fact, Insight and User Profile generation refer to the individual subject as "the user" without inferring gender; exact source quotes remain unchanged. An explicit User Profile refresh advances eligible delayed L2 work, waits for it to settle, then [freezes eligible L2 Insights and exact Profile Data](../src/oam/profiles/inputs.py) before publishing L3. L1 facts and L0 passages ground Insight citations rather than supplying independent Profile claims; L1-only changes do not change generation input identity. The [Profile prompt](../src/oam/profiles/prompt.txt) enforces that boundary. Resources instead produce detailed passages and a derived abstract; neither output is an input to L1, L2, or L3.

[Extraction prompt selection](../src/oam/indexing/extraction.py) keeps entity, alias, temporal and state-update extraction in the common prompt. `index.enable_causal_graph: false` is the default; setting it to `true` appends [causal instructions for the shared example](../src/oam/indexing/extraction-causal-suffix.txt). Singleton extraction, grouped extraction, reference admission and overflow retries use that same effective prompt. Validation strips unsolicited causal fields while disabled and preserves the remaining supported fact. The indexing choice participates in [generation identity](../src/oam/indexing/identity.py), independently of query-time causal settings.

[Insight synthesis](../src/oam/indexing/extraction.py) can also supply a short supported subject, project or purpose label for semantic retrieval. [Incremental consolidation](../src/oam/indexing/consolidation.py) and [support-removal repair](../src/oam/governance/repair.py) embed that label when supplied and otherwise embed the full synthesis. The stored and answer-visible Insight, lexical text, support IDs and citations retain the complete supported claims, measurements and action status. Each Insight still has one semantic vector and one candidate per retrieval arm; L1 vectors remain unchanged. The label is internal indexing metadata. The [indexing identity](../src/oam/indexing/identity.py) includes the incremental recipe and its producing limits only when Insights are enabled. Existing collections are never automatically relabelled or rebuilt.

Ordinary L2 work maintains knowledge across source increments. The [consolidator](../src/oam/indexing/consolidation.py) groups related unexamined facts around the oldest pending seed using the configured semantic-link similarity floor, then interleaves eligible dense and lexical matches to existing Insights. Similarity proposes candidates; the [incremental synthesis rules](../src/oam/indexing/incremental-insight-prompt.txt) require supported identity before UPDATE. Each request includes complete admitted target bodies and bounded historical L1 evidence under the complete input budget. The canonical limits are eight new seeds, eight target bodies, 64 total facts and 64,000 completion tokens, including provider reasoning tokens. A request that cannot fit reduces its seed group; it never truncates an admitted target or treats a failed lookup as an empty collection. Every presented seed receives exactly one model decision: UPDATE, CREATE, KEEP_TEXT or NO_INSIGHT; deferred seeds stay unfinished. The shared model projection includes fact IDs and text, known roles and statement times, available temporal annotations, seed IDs, and complete admitted target text with every nonempty retrieval label. Missing optional values are omitted. Source references, target revisions, complete support history, subtypes and vectors stay private; labels are derived context, not independent support.

An UPDATE preserves the Insight ID, advances its revision and unions prior eligible support with relevant supplied support. A CREATE gets an identity stable across compatible retries. Text, support, current search projection and seed completion publish in one [guarded transaction](../src/oam/indexing/store.py), after model and embedding calls finish. Expected revision, direct removal and every retained support are rechecked, so failed or stale updates preserve the last eligible revision. Unchanged embedding input reuses its vector, including support-only revisions. The model returns KEEP_TEXT with selected supplied supports when existing wording remains correct. The backend binds the captured revision and resolves that decision to a support-only UPDATE preserving exact text, label, subtype and vector, or to internal NO_CHANGE when all selected support is already retained. NO_CHANGE adds neither a revision nor an embedding; NO_INSIGHT records examination while retaining L1. Completed groups survive retry, and existing bounded worker retries own unfinished work. Changed L2 inputs make a stored Profile non-current without generating L3.

Packing and dispatch use the same lean projection and complete-message input budget. Checkpoints bind that projection together with full captured facts and target state, configuration, generation and the [model-boundary recipe](../src/oam/indexing/identity.py), so private changes prevent reuse even when model-visible text is identical. [Support-removal repair](../src/oam/governance/repair.py) loads existing temporal annotations from every remaining eligible supporting fact and applies the same fact projection. The complete surviving support set must fit before the separate single-synthesis request; repair has no incremental target actions or KEEP_TEXT. Existing removal, revision and publication guards remain authoritative.

```text
eligible interactions -> L0 -> L1 -> supported L2 --+
                                                   +-> requested L3
explicit Profile Data      --------------------------+
stored L3 -> independent GET /profile -> caller-owned personalization
query -> authorized retrieval -> relevant L0/L1/L2 + Evidence -> bounded recall
stored L3 ------------------------------------------------------X-> recall

text/HTML/PDF/image upload or HTTPS URL -> immutable original -> passages + abstract -> joint recall
Resource ----------------------------------------------X-> L1/L2/L3
```

Every generated claim retains support to immutable source versions and locators. Source revision or deletion changes eligibility before a response or worker publication can use the old derivative.

The [runtime prompt index](prompts.md) links the packaged text files consumed by fact extraction, Insight synthesis, default Profile generation, Resource reading, query planning and deployment preflight. Each authored instruction has one runtime-owned text file; the relevant consumer assembles request-specific input separately.

The [Resource parsers](../src/oam/resources/) retain native PDF page text, render scanned pages and text pages with a large image or vector table for [visual extraction](../src/oam/workers/index_source.py), and cite physical PDF pages or image regions when known. Text fact extraction and visual document extraction use the same `extraction` model binding, which must support both text and vision. The [model adapter](../src/oam/models/runtime.py) sends bounded image bytes to that binding; [indexing](../src/oam/indexing/store.py) counts its measured usage. Detailed text passages enter the existing embedding and lexical indexes; image pixels do not become search vectors. The `embedding` role selects a separate binding, while `index.embedding_dimensions` remains the sole configured vector-size owner for runtime validation and database initialization. A failed later PDF page leaves completed passages marked as partial, and a failed abstract does not erase detailed passages.

[Canonical configuration](../configs/oam.yaml) owns one service-wide VLM model and OpenAI Chat protocol through `models.vlm`, with declared `text` and `vision` capabilities. Each generative role selects only its `none/low/high/max` effort in `models.reasoning_effort`; a null effort leaves that role disabled. [Binding resolution](../src/oam/models/bindings.py) freezes the shared model, endpoint, credential and role effort, then derives thinking disabled for none or thinking enabled plus explicit effort for the other levels. Both [runtime generation](../src/oam/models/runtime.py) and [capability preflight](../src/oam/models/client.py) use that same parameter translation before the existing Chat dispatch and response validation. Embedding and optional reranking retain separate non-generative definitions. [Index generation](../src/oam/indexing/identity.py) includes resolved indexing-role model, endpoint, protocol and effort; configuration changes never silently rebuild an existing collection.

The [PDF child boundary](../src/oam/resources/pdf_isolated.py) runs local parsing, page inspection and rendering outside the durable worker with a parent-enforced timeout and bounded transfer. The worker keeps model calls and publication in its own process; a child crash or timeout produces a Resource failure without an in-process parse retry.

The [image preparation path](../src/oam/resources/images.py) validates the original format, bytes and hard input-pixel limit before full decoding. Images above `resource.max_pixels_per_image` are downscaled only in the vision-input copy, preserving aspect ratio, displayed orientation and transparency; smaller images retain their exact bytes. The [PDF renderer](../src/oam/resources/pdf.py) lowers its render scale before allocating an oversized page and reports actual bitmap pixels. The aggregate `resource.max_total_pixels` limit counts original image pixels or rendered PDF pixels and still rejects exhaustion instead of shrinking later pages to an arbitrary remaining budget. Originals and normalized citation regions remain unchanged. [Indexing identity](../src/oam/indexing/identity.py) binds the vision preprocessing recipe and pixel target to the generation, preventing changed model input from mixing with previously published passages; adopting this recipe for existing collections requires an explicitly authorized rebuild. Vision checkpoints also include the processed image hash.

Native PDF text preserves extracted line breaks and indentation. The [Resource worker](../src/oam/workers/index_source.py) applies the existing ingestion chunk limits within each unannotated physical page and records page-relative character offsets in the parsed text. A page producing one passage retains its page block locator; a larger page produces span-qualified locators. These native passages use parse revision 2 in both stored rows and citations. Pages targeted by caller-supplied exact temporal annotations retain the legacy flattened whole-page representation and parse revision 1, preserving their quoted spans and annotation ownership. Original bytes remain unchanged. The indexing recipe changes with this derivation; existing collections require rebuilding for the new generation before current-generation serving.

Resource abstracts use all complete passages when the full prompt fits. For larger inputs, the worker considers the first and last passages, then progressively bisects the remaining source intervals; it skips candidates that do not fit and restores source order before the single abstract call. Any omission remains explicitly partial coverage. Detailed passages stay independently searchable, and an abstract remains a Resource derivative rather than original evidence or Learned Memory.

The [HTTPS Evidence fetcher](../src/oam/resources/url_fetch.py) accepts a caller-declared HTML/PDF/PNG/JPEG type only after the retain caller is authorized. It resolves a public address, connects to that checked address with TLS hostname verification, refuses redirects and compression, and stores the bounded returned bytes as the immutable original. A committed identical URL request reuses its receipt without another fetch. URL query data is excluded from stored display provenance and public errors; workers parse the stored bytes and never revisit the URL.

An L1 memory unit is one concise, independently addressable fact sentence with a stable `memory_id`; raw passages and L2 Insights remain distinct kinds. [HTTP admission](../src/oam/api/app.py) and [runtime composition](../src/oam/api/runtime.py) accept `/v1/retain` JSON interactions and `/v1/users/{user_id}/resources` document text, URL or file originals, while `/v1/users/{user_id}/profile-data` accepts structured user information. Public callers never manage source/message IDs or revision numbers on retain; Resource and Profile Data item `PUT` revisions supply `If-Match`, while [source storage](../src/oam/db/sources.py) assigns the next immutable revision. The [indexing worker](../src/oam/workers/index_source.py) validates exact caller annotation quotes and publishes caller clocks/times on passages and supported facts. Missing extraction does not erase caller-annotated raw evidence. Source deletion is available; removal of one generated fact remains a later separate control.

[L1 extraction](../src/oam/indexing/extraction.py) loads its shared rules from [extraction-prompt.txt](../src/oam/indexing/extraction-prompt.txt), with the packaged [grouped prefix](../src/oam/indexing/extraction-group-prefix.txt) and [reference suffix](../src/oam/indexing/extraction-reference-suffix.txt) selected by the existing call path. The shared prompt groups selection criteria, output and grounding, entity identity, and time rules before its examples. It keeps explicit personal facts, preferences, experiences, plans, goals, decisions, constraints and meaningful secondary context. Assistant conclusions, consequential recommendations and performed actions qualify when useful and grounded; generic exposition, illustrative examples and advice inventories without specific ongoing context are omitted. All eligible original passages remain in L0. Compact model output omits empty arrays and the default fact category while retaining supported preference/experience categories, named entities, relations and date annotations. Singleton calls omit passage identifiers and validate against their one offered center. Grouped calls use short call-local passage identifiers; [validation](../src/oam/indexing/grouping.py) checks each exact quote against its offered owner before restoring the canonical passage identifier for checkpointing and publication. A missing or invalid owner is recovered only when its unchanged nonblank quote occurs exactly once across all offered passage bodies; context-only references, ambiguous matches and quotes contradicting a valid owner remain rejected. Recovery preserves the output index, records a `recovered_passage` diagnostic and marks extraction coverage partial. Recursive split calls rebuild their own identifier mappings. Each fact is supported by its owning passage identifier and one exact contiguous quote, with no character offsets in model input/output or persisted fact citations. [Extraction validation](../src/oam/indexing/extraction.py) requires a unique unchanged quote in that passage; a repeated quote needs longer source context. Caller and generated time annotations share one strict four-field contract: role, timezone-aware start/end and exact quote. Equal bounds describe a source-supported point; increasing bounds describe periods, with precision, uncertainty and duration wording retained in fact text and quote. The extraction prompt instructs the model to use message timestamps as statement provenance and only as anchors for explicit, determinate relative dates attached to the same event. Undated completed events and vague recency retain their facts without invented dates in text or annotations; a date attached to another event supplies no missing event date. Today and yesterday resolve to whole local calendar days, including timezone transitions. The default extraction role uses low reasoning to apply these distinctions. Publication derives point/period SQL bounds directly from equality, appends origin and source-envelope reference timezone, and accepts no redundant temporal flags or per-annotation provenance inputs. [Existing-fact references](../src/oam/indexing/references.py) and L2 inputs project persisted dates through the same four-field model; storage provenance stays separate from model annotation semantics. [Publication](../src/oam/workers/index_source.py) stores the quote with source/message identity and matches caller-supplied time quotes using temporary positions derived from the unchanged owning message. Caller quotes crossing a chunk boundary remain attached to overlapping original passages; facts inherit only fully contained caller quotes. [Context rendering](../src/oam/retrieval/context.py) checks source/message identity and quote membership in the cited passage before sharing its source block. Passage locators use source/version/message identity and a zero-based passage index; caller temporal annotations likewise require an exact unique quote without character coordinates. Resource locators retain document/block/page/region identity. The [indexing recipe](../src/oam/indexing/identity.py) changes with this extraction contract, preventing reuse of prior extraction checkpoints.

Quote validation uses unchanged original text only. Missing, rewritten, formatting-normalized or ambiguous quotes are rejected. A repeated quote needs longer exact source context; no coordinate escape hatch or fuzzy repair is accepted. Temporal quotes must occur exactly once within their accepted fact support. Recursive split results are checked again against their original canonical passage before checkpointing; a quote unique only in a retry child cannot bypass the canonical owner check.

The complete serialized extraction input is checked after reference packing. If escaping or prompt overhead makes it exceed `extraction.max_input_tokens`, extraction splits the offered source inputs within the existing canonical passage checkpoint before dispatch. Each child retains exact source text and passes the same bound and support validation. Only actual model calls contribute usage; an unsplittable local input fails explicitly. Compatible successful checkpoints remain unchanged.

The [chunker](../src/oam/indexing/chunker.py) uses `chunk.ingestion` to split each message or document into exclusive source passages before either singleton or grouped extraction. Recall's `include.chunks` is a strict boolean that defaults to true and controls full source bodies rather than ingestion boundaries. [Indexing identity](../src/oam/indexing/identity.py) includes ingestion chunk settings and excludes recall-only settings; [capabilities](../src/oam/api/app.py) publish mode context caps separately from ingestion settings.

The [source worker](../src/oam/workers/index_source.py) publishes interaction facts and temporal links, then atomically stores a source/version/generation-qualified seed manifest, enqueues dependent semantic work and succeeds its direct claim while keeping the source operation running. Direct facts remain searchable before linking completes. The [semantic processor](../src/oam/workers/semantic_links.py) computes bounded ANN proposals outside the user-row lock, publishes short guarded batches, and completes source readiness under its own claim; valid empty seed sets complete without ANN. Compatible retries reuse published facts and embeddings. [Claim admission](../migrations/0029_semantic_claim_gate.sql) honors `worker.claim_semantic_links`; disabling it holds semantic tasks without consuming claims or attempts. An operator can use this setting across every worker in a fresh isolated closed import, validate its declared source/version/generation and extraction coverage, drain direct workers, then enable semantic claiming and wait for all link readiness. This is an operational gate, not a durable import-wide API. Saved inline semantic phases remain resumable, and [lease settlement](../migrations/0028_inline_semantic_lease_settlement.sql) preserves direct memory on exhausted linking failure. When enabled, separate L2 consolidation is scheduled at successful semantic completion, and its configured delay starts then.

Independent source operations run concurrently through the existing durable queue and [worker runner](../src/oam/workers/runner.py), bounded by `worker.max_tasks` and `user.concurrency`. A client processing a batch can submit a bounded window of independent sources before waiting for completion; it retains every receipt and waits for every operation's required readiness flags before consuming the completed batch. Admission order does not imply completion order, and available cross-source reference facts can differ from serial submission. The [model runtime](../src/oam/models/runtime.py) gives generation and embedding separate budgets; deployment-wide PostgreSQL permits cap them independently. [Indexing transactions](../src/oam/indexing/store.py) acquire separate transaction advisory slots defined by [migration 0024](../migrations/0024_indexing_db_admission.sql), bounded across replicas by `database.indexing_concurrency`. Local admission limits connection creation before waiting for those shared slots. Commit, rollback and connection loss release the DB slots, and remote model calls hold none. Each source retains its own originals, version, claim, fence and checkpoints.

The [group planner](../src/oam/indexing/grouping.py) combines adjacent eligible passages from one source into a bounded L1 call by default. It fixes group membership before embedding/concurrency batches, breaks at eligibility gaps, and keeps complete passage text, individual roles, message timestamps and stable passage ownership. Group size respects the serialized input bound, passage/fact cap and a conservative output estimate (three times source-text tokens plus 128 tokens per passage), bounded separately by `extraction.group_max_estimated_output_tokens: 4096`; this estimate cannot guarantee model coverage. Extraction and complete-support removal repair use `extraction.max_output_tokens: 64000` as their completion cap; ordinary incremental L2 uses `index.insight_max_output_tokens: 64000`; Resource vision and abstracts use `resource.max_output_tokens: 4096`, leaving room for reasoning and visible JSON. Length-terminated output raises a typed overflow error. Indexing then recursively halves a group at passage boundaries, or splits a singleton source span near a sentence boundary while preserving exact source text and canonical passage ownership. Split results merge in source order with remapped fact relations and cumulative usage, including overflow attempts. A source span of at most 500 non-surrounding-whitespace characters, or a span that cannot form two nonempty halves, fails rather than being dropped. Each split child rechecks cancellation and source eligibility and renews its fenced lease before dispatch, with no transaction held during the model call. Branches share the existing outer checkpoint; a completed merged extraction is reused on retry, while an interrupted or failed split tree may repeat its successful branches. Oversized groups split at passage boundaries, and a singleton uses the original extraction protocol. Each grouped fact names its owning passage; validation checks that passage alone. The worker publishes a whole group and its cross-passage relations in one fenced transaction, and retries reuse its completed checkpoint. `extraction.group_max_passages: 1` restores singleton grouping; the canonical value is 64. Grouping uses a distinct indexing generation, so existing collections require an explicit rebuild rather than automatic data replacement.

Existing-fact context is enabled by default with `extraction.reference_max_facts: 10` and a configurable `reference_max_input_tokens: 2048` estimated-token target; setting the fact limit to 0 disables it. [Reference selection](../src/oam/indexing/references.py) reuses passage embeddings to rank currently eligible L1 facts from other sources in the same tenant, user and generation, and freezes complete candidate text, identities, roles, mention dates and time qualifiers before extraction. [Wire packing](../src/oam/indexing/extraction.py) derives one proportional text preview per candidate using a shared scale after accounting for serialized metadata. The nearest complete sentence or comma-clause boundary may exceed the soft target; decimal numbers and numeric separators remain intact. Short and long texts use the same proportion, without short-first reservation or redistribution. Shortened text is marked `text_truncated: true` and treated as incomplete context whose omitted qualifiers and negation are unknown. Full stored facts and new source evidence remain unchanged. The complete model-input limit stays hard: admission retains a prefix of the relevance order and removes only whole reference records that cannot fit. Singleton/group calls and split retries derive views from full frozen candidates, avoiding repeated normalization. New facts still require current-source quotes, and distinct occurrences retain their own support. Optional existing relationship IDs are validated diagnostics, never support or directly published links. Completed extraction results are reused; unfinished calls remove references that became ineligible. Reference settings and the indexing recipe change generation, requiring an explicit rebuild for existing collections. Functional wiring does not establish a quality or latency gain; matched real evaluation remains required.

Resource revision and source deletion use distinct owner grants introduced by [source-control migration](../migrations/0009_source_controls.sql); [asserted-user grant migration](../migrations/0012_asserted_resource_grants.sql) gives new `dev` and `trusted` users those grants. The [follow-up migration](../migrations/0013_asserted_user_resource_grants.sql) upgrades existing asserted users that retain the original narrow grants, while preserving keyed-user and customized grants. Migration 0014 restricts the registration function owner and execution permissions. Revision commits a new current version and advances the user's policy epoch, excluding the previous version before reindexing. Deletion commits all-version exclusion, cancels outstanding source work and returns a separate cleanup operation in one transaction. [Eligibility SQL](../src/oam/db/eligibility.py) requires every support of a derived L1/L2 version to remain current; [recall](../src/oam/retrieval/service.py) and [inspection](../src/oam/db/inspection.py) recheck the policy before returning content. [The cleanup worker](../src/oam/governance/cleanup.py) removes affected passages, facts, Insights, vectors, original bytes and server-held export parts under a fenced durable claim. Unrelated active sources stay eligible. Stored User Profile reads validate current eligible inputs before returning supported fields.

Write admission follows mode-specific identity admission → shared HTTP/write capacity → bounded incoming bytes → JSON/multipart parsing and semantic limits → bound user and grant check → idempotency and intake capacity → atomic source/receipt acceptance. The [request middleware](../src/oam/api/admission.py) holds one PostgreSQL session admission slot through application execution and response completion; a rejected write consumes no total slot and its body is not read. Read routes, including POST search, can use the request slots reserved from writes. Any root-key verification transaction closes before waiting on the upload. Both write endpoints count actual received bytes against `api.max_request_bytes`, including chunked bodies; overflow stops parsing with `413` and closes partial upload files. This encoded-body cap is distinct from the accepted content/original limits and has one owner in [canonical configuration](../configs/oam.yaml).

[Fact-link construction](../src/oam/indexing/links.py) materializes only eligible new seeds. Direct indexing publishes temporal links, then atomically settles `index_source` and schedules one dependent `index_semantic_links` work unit under the same source operation, with a deterministic identity and immutable seed-manifest digest. Direct facts remain usable with `memory_ready=true`, `temporal_links_ready=true` and `links_ready=false`; operation status remains running (public HTTP status `processing`), and recall diagnostics remain pending. A zero-seed source follows the same queued handoff and completes without ANN when its semantic claim runs. The [semantic worker](../src/oam/workers/semantic_links.py) reads at most 1,000 seeds at a time in a separately bound, read-only transaction without the user-row lock or projection-epoch updates. Semantic neighbors query the persistent vector table in ascending cosine distance, making its existing HNSW index available to the planner. Current tenant/user, generation and source-support eligibility, self exclusion and prior-link capacity apply before the neighbor limit; positive weight and minimum similarity apply to the bounded result. The shared support predicate validates every support through exact passage, evidence, source-version and source primary-key lookups, avoiding repeated whole-user parent joins before planner statistics settle. Publication groups proposals by seed once and inserts retained edges in one bulk statement. Publication uses short [guarded transactions](../src/oam/indexing/store.py), rechecks both endpoints and the remaining per-seed cap, deduplicates edges and rechecks the lease before committing. Database statement timeouts bound semantic reads and writes; each batch renews the existing lease, and batches run sequentially within each claim. `index.semantic_link_ann_iterative_scan` and `index.semantic_link_ann_scan_max_tuples` own transaction-local index-time ANN tuning independently of recall settings. Approximate search may underfill or select different neighbors from exhaustive search; index existence alone does not prove physical index use or quality. Final guarded completion sets `links_ready=true`; retryable database failures reuse the same work unit, while terminal or [exhausted expired work](../migrations/0023_semantic_lease_settlement.sql) preserves direct memory and reports partial failure. Existing delayed Insight consolidation is scheduled at successful semantic completion and retains its separate operation and readiness.

Temporal links retain exact gap, horizon and deterministic witness rules. Point-time construction returns at most the configured neighbor count before and after each seed timestamp, then selects the exact combined gap/ID top-k. Interval construction uses range overlap to find annotation pairs and selects one canonical best witness per target before applying the unit-neighbor cap. Intermediate projections carry only seed identity plus the applicable vector or timestamp, or annotation witness data. Publication remains inside the existing guarded transaction and requires complete link stages. The changed link recipe produces a new [index generation](../src/oam/indexing/identity.py); existing projections and queued work are not reassigned to it.

Exact learned-record removal is owned by [removal admission](../src/oam/governance/removal.py), [projection cleanup](../src/oam/governance/cleanup.py) and [Insight repair](../src/oam/governance/repair.py). The [versioned migration](../migrations/0026_memory_removal.sql) adds a typed, user-qualified unique removal identity to existing operations. API admission checks `source:delete` and locks the user row before atomically excluding the selected ID, advancing policy/projection epochs, closing affected Insights and Profile snapshots, and persisting cleanup plus source-scoped consolidation work. The receipt retains only IDs/revisions/support metadata; no old synthesis is needed for repair. Cleanup finishes before repair through a durable work dependency and preserves L0 originals. Repair reuses bounded synthesis validation and checkpoints, rechecks current support and direct-removal tombstones under the publication lock, and either publishes the same Insight ID at a new revision or records valid insufficient support. Extraction and ordinary consolidation also check tombstones, preventing retry/rebuild resurrection. A repaired Insight cannot reopen a closed Profile snapshot; explicit Profile refresh owns new L3 publication.

Routine learning uses the existing extraction and L2 paths. The [extraction rules](../src/oam/indexing/extraction-prompt.txt) retain substantive content, interaction and workflow choices as dated request observations without inferring completion or a lasting preference. [Insight inputs](../src/oam/indexing/extraction.py) carry each fact's source role from its persisted locator, alongside source references and supported dates; unknown roles remain unknown. [Ordinary consolidation](../src/oam/indexing/consolidation.py) supplies that provenance to its [incremental rules](../src/oam/indexing/incremental-insight-prompt.txt); [repair](../src/oam/governance/repair.py) uses the [complete-support rules](../src/oam/indexing/insight-prompt.txt). Both retain the same attribution and chronology constraints. The existing `patterns` subtype requires distinct occurrences or a supported trend, preserves the observation period, and distinguishes automation and generated content from personal behavior. Ordinary habits require no host task ID. The changed [indexing recipe](../src/oam/indexing/identity.py) requires an explicit rebuild for existing collections; prior projections and queued work are not relabelled.

## 3. Durable Work

[Removal maintenance recovery](../src/oam/operations/repository.py) follows the existing HTTP → authorized user lock → durable work → publication path without a new queue or recovery registry. `POST /operations/{original_removal_operation_id}/recover` requires `source:delete`, keeps the original removal receipt and exclusion, and rearms only failed cleanup or exact recorded linked repair work with its saved inputs and dependencies. Cleanup deletes target-owned `search_units` rows, including their semantic vectors, before dependent repair can publish a newly supported Insight revision. Completed cleanup/progress and compatible model checkpoints remain unchanged; queued or running work is not duplicated. Recovery fences the selected terminal work, renews the configured attempt budget and atomically enforces the existing pending-root admission cap. Cancelled or source/generation-ineligible repair is not retargeted, and unknown model outcomes require the existing attempt-reconciliation authority before recovery. Expired work still marked running is outside this endpoint's terminal-only contract. The [API routes](../src/oam/api/app.py), [runtime admission](../src/oam/api/runtime.py), [cleanup worker](../src/oam/governance/cleanup.py) and [repair publisher](../src/oam/governance/repair.py) retain their existing ownership and eligibility guards.

An accepted write commits its source/original bytes, idempotency identity, root operation, sealed stage manifest, and first runnable work units before returning `202`. Workers claim ready rows with short PostgreSQL transactions, leases, and monotonically increasing fences; remote model I/O happens outside the transaction. Public [operation retry](../src/oam/operations/repository.py) creates linked work only for failed/cancelled units and reuses compatible checkpoints; the [HTTP handler](../src/oam/api/app.py) returns `409 RetryRequiresReconciliation` when selected work has an unresolved external attempt, before any replacement work is created.

[Intake accounting](../src/oam/db/queue_admission.py) counts unfinished logical root requests under the existing user lock. A delayed consolidation child retains its source root's slot, automatic retries retain the same slot, and an explicit retry creates a new admission. Exact idempotent reuse and unchanged User Profile refresh require no new slot; deletion cleanup is exempt. The [claim function](../migrations/0018_profile_dependency_settlement.sql) serializes count-and-claim for a user and enforces two live claims across runners, skipping a capped user so other users can progress.

[Shared model admission](../src/oam/capacity.py) bounds generation at 32 calls and embeddings at eight across the deployment. Background indexing and foreground search share the eight embedding permits by default; `provider.embedding_search_reserved` optionally withholds permits from background work. Neither consumes a combined generation/embedding allowance. The [model client](../src/oam/models/runtime.py) commits dispatch intent before remote I/O, propagates its remaining deadline, and retains permits after uncertain transport outcomes. Known completion releases capacity independently of output validation. Operator [permit commands](../src/oam/models/permits.py) inspect and reconcile uncertainty, including foreground calls without a durable work operation; forced release remains explicitly unverified until remote completion is known. The [capacity migration](../migrations/0015_shared_capacity.sql) grants runtime roles only narrow metadata functions.

The [source repository](../src/oam/db/sources.py) takes the existing collection lock before checking request idempotency or allocating source/revision identities. A text document's `append` reads the current text, concatenates the exact supplied delta without separators and validates the completed size inside that same transaction, so concurrent appends cannot lose content. Documents use a stable `document_id`; Resource `PUT` requires `If-Match` and rechecks it at acceptance, while a matching idempotent retry reuses its prior receipt. File append is rejected. Source activation rejects deleted sources; ordinary original reads require an active current version. The [current claim function](../migrations/0016_queue_admission.sql) locks work rows without escalating queue privileges and withholds any unit with an unresolved external outcome until explicit [attempt reconciliation](../src/oam/operations/repository.py). The [indexing worker](../src/oam/workers/index_source.py) consumes accepted claims, persists compatible model-stage outputs and publishes supported representations. User-qualified operation routes expose readiness under the same grants. The [core acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) names the remaining proof.

The [entity publisher](../src/oam/indexing/entities.py) stores generation-qualified stable identities separately from [individually supported name rows](../migrations/0027_entity_names.sql). The existing extraction call can declare an explicit source-quoted alias or reference an offered fact for a grounded same-object mention; names alone never merge identities. Name normalization affects lookup keys only. Original passage/fact text and complete recall queries remain the dense embedding inputs. Legacy string memberships do not acquire IDs automatically; populated collections require an explicitly authorized fresh-generation rebuild.

Publication rechecks operation cancellation, lease/fence ownership, source version, learning eligibility and generation. Direct indexing of an independent active source may continue across another source's policy change; L2 consolidation also checks its frozen policy epoch because its input set can cross sources. A late or stale worker may preserve diagnostic attempt evidence but cannot publish canonical output. Retry reuses compatible completed work and creates a new attempt only for unfinished eligible stages.

A completed model response retains independently validated usage even when its generation is truncated/refused/empty or its embedding/scoring output is invalid. The [model adapter](../src/oam/models/runtime.py) carries that metering to the [existing attempt failure path](../src/oam/indexing/store.py); unavailable or malformed metering is never invented. Retryable extraction/Insight JSON/schema output uses the remaining durable claim budget: finalize the failed attempt and requeue its work atomically, then reuse completed stage checkpoints on the next claim. A completed, unrefused model response with explicitly null, empty or whitespace-only content and no reasoning or tool-call output also uses that remaining indexing claim budget. Explicit `no_facts` succeeds without retry, and semantic-link retry policy remains unchanged. Other model-adapter output rejection and input/output limits are not automatically retried merely because their usage is known. Network timeouts without a received response remain unresolved and are never automatically replayed. Successful-stage and known failed-attempt tokens are counted once each for the same source revision and generation; exhausted retries remain an explicit partial failure.

## 4. Retrieval and User Profile

The embedding binding owns an optional `query_prefix`, empty by default. [Recall query encoding](../src/oam/retrieval/service.py) prepends it exactly once to the complete original query; lexical retrieval, time inference and answer-facing query text retain the original input. [Document embedding](../src/oam/models/runtime.py) remains unchanged. Query formatting changes the effective runtime configuration identity without invalidating the document index.

The [source-original read](../src/oam/retrieval/repository.py) ranks eligible user passages by the complete query vector within the exact source revisions of bounded interaction discovery seeds. [Recall assembly](../src/oam/retrieval/service.py) collects ranked originals and source support before final admission. The [context selector](../src/oam/retrieval/context.py) considers eligible learned and original roots in final relevance order under one complete-rendering cap: fast defaults to 18,000 tokens and normal to 32,768. Independent originals remain selectable without extracted facts or when a learned bundle cannot fit. Learned roots require complete eligible support, including required facts and citations and, by default, full original bodies. `include.chunks: false` omits every full source-body item and block while preserving learned support and genuine citation quotes. Source eligibility is validated in either representation. Complete tentative selections, including all metadata, must fit before admission; shared chunks are counted once, and oversized bundles are omitted whole without clipping. If the only eligible L1 fact has an oversized complete bundle and no higher-ranked root was admitted, return it alone, stop filling and report the overshoot; Insights have no such exception. Each unique learned item and full original consumes a slot in its respective `max_results` pool. Source discovery and supplemental recovery grant no additional fusion vote. Runtime counting metadata identifies the estimator; exact answer-model counting remains an independent caller boundary.

The [dense read](../src/oam/retrieval/repository.py) uses a stable unit-ID tie-breaker after cosine distance when ranking an exact user-scoped pool, so equal similarity scores have a defined order before the candidate limit. Small fast requests retain their approximate HNSW query shape.

The [temporal stage](../src/oam/retrieval/service.py) independently searches a query-relevant eligible fact pool within the requested window, even when direct retrieval already found dated evidence. It merges those candidates with qualified dense roots before the existing bounded bucket/seed selection and spreading; newly selected roots and discoveries contribute to one temporal arm with ordinary time-witness revalidation. Each breadth-first frontier uses one synchronous neighbor read. For each parent, both temporal directions and, when the mode enables causal retrieval, outgoing causal links first apply source/target eligibility, semantic floor, time-witness and optional edge-ID checks, then select their highest-ranked eligible neighbors through the existing edge indexes. Their union receives the unchanged per-parent weight/target-ID/edge-ID ordering and cap, avoiding a full-frontier edge scan without admitting a raw link before validation. Expiration discards the unfinished frontier. The channel limit, semantic floor, root/node/neighbor caps and absolute deadline remain shared. Explicit time bases remain separate, and source-message timestamps do not substitute for missing event annotations.

The [lexical read](../src/oam/retrieval/repository.py) orders each term's matches before validating source support, then continues until it fills that term's eligible candidate cap. Full-query and primary-term conjunctions retain precedence. Partial matches use whole-query OR cover density divided by indexed document length, computed once per matching unit, so repeated single words do not crowd out concise evidence matching several query aspects. Eligibility precedes every cap, and the combined term lists contribute one lexical fusion vote.

The [recall service](../src/oam/retrieval/service.py) and [eligible SQL repository](../src/oam/retrieval/repository.py) implement one non-generative fast/normal pipeline. An explicit ranking window wins; otherwise [deterministic query-time parsing](../src/oam/retrieval/query_time.py) resolves one event window from a supported date expression or an explicit two-endpoint absolute calendar interval. Calendar intervals include the final day/month/year and convert both local boundaries independently to UTC; explicit windows still win, inferred basis stays event, and the full original query is embedded unchanged. Ambiguous, invalid or unsupported implicit dates disable only the temporal arm and produce diagnostics, not request failure. FTS and narrow literal matches form one deduplicated lexical rank list under one shared cap and contribute one fusion vote per unit; temporal direct seeds use that same list. Both modes fuse dense, lexical and optional temporal arms; their configured graph selection may add one ordinary graph arm, for at most four arms. Ordinary graph retrieval remains free of date exclusion, while temporal spreading uses strict basis/window-qualified seeds, neighbors and path witnesses. Tenant/user, source and generation eligibility remain hard constraints everywhere; the [acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) still requires its full HTTP and evaluation matrix.

Each [readiness check](../src/oam/retrieval/repository.py) selects generation-qualified operation IDs once within its SQL statement, then selects the latest non-consolidation operation for every active source version together. Pending and partial coverage still reflect current base indexing work. Recall retains fresh generation and parse checks before context hydration and a final policy-epoch check before returning content.

The [lexical recipe](../src/oam/retrieval/fts.py) routes English words to PostgreSQL `english`, numerals and pinned Jieba search terms to `simple`, and retains protected negation and time words. [HTML parsing](../src/oam/resources/html.py) preserves available title, heading and table caption fields for A/B/C ranking weights while passage text keeps D; other current sources supply D only. Recall combines distinct content terms with OR, retrieves a bounded ranked list per informative term, and preserves primary/full-match priority before each cap and final fusion. Configured `ts_rank_cd` field weights rank each term; recency breaks equal relevance before stable unit IDs. Exact-anchor results use the same bilingual representation to rank the remaining query words. The [schema migration](../migrations/0008_bilingual_fts.sql) adds a separate GIN-indexed bilingual vector and keeps the prior lexical vector available to older replicas; populated older generations require an explicit projection rebuild before this runtime can search them.

Fast uses its shorter deadline and caps temporal nodes at `min(search.temporal_nodes, search.fast.max_results)`, so pre-agent recall can follow temporal links. The [mode configuration](../configs/oam.yaml) owns `search.fast.graph` and `search.normal.graph`, with defaults `"off"` and `light`. Off skips entity/alias and semantic expansion, light follows stored entity/alias paths, and full adds stored semantic neighbors. Independently, `search.fast.causal_graph` and `search.normal.causal_graph` default to `false` and enable two outgoing causal hops in ordinary expansion and causal edges in temporal spreading. A true causal flag can run the existing graph arm with `graph: "off"`, without entity or semantic expansion. Both modes support all three selections within their existing caps, deadline and context budget. The [configuration model](../src/oam/config.py) rejects invalid selections and the removed global `search.fast_graph` key. An omitted or null fast-only `fast_graph` request field inherits `search.fast.graph`; explicit true selects light and false selects off. The [direct, batch and planned search handlers](../src/oam/api/search.py) preserve this override. Graph and causal selections, executed stages, degradation and timings are recorded in recall diagnostics and traces; correlated execution logs report the selected path and outcome. Graph expansion shares eligible fact proofs and validates name support only for entities linked to eligible seeds, retaining canonical and alias proof from nonseed facts before applying membership caps. Every fast request skips reranking. Recall SQL disables JIT and selects custom plans only within each read transaction, so pooled connections plan against the current tenant/user cardinality rather than generic estimates from another scope. Supported database clients send each statement’s timeout setup and query together in order, then drain results before fetching or releasing the owning transaction; clients without pipeline support retain serial execution. Normal uses its configured graph selection and reranking when bound. Terminal entity, one-hop semantic and second-hop causal candidates exclude every graph seed before their respective caps; identity support and causal first-hop intermediate seeds remain available. Both fast and normal can still return L2 Insights through direct dense or lexical search. The canonical configuration gives normal's graph arm weight 0.1 and its other executed arms weight 1.0; fast gives its executed arms equal weight. Fast has at most three arm types by default and four with graph enabled; normal has at most four. Normal's [configured arm weights](../configs/oam.yaml) can be overridden together or separately. A hit found by both dense and graph receives both fusion votes and one final item with its path evidence. Final [context admission](../src/oam/retrieval/service.py) follows fused or configured reranker relevance order across evidence types; source diversity affects only bounded original discovery. Related-fact SQL orders eligible candidates before selecting its bounded result. Related facts, ordinary source-window passages and support companions are gathered before final admission, where the complete rendering must fit one mode total and each pool retains its result cap. The [graph activation](../src/oam/retrieval/algorithms.py) uses `n * n / (n * n + 1)` for `n` distinct shared entities, plus the strongest semantic and causal links, to order that arm. [Lexical retrieval](../src/oam/retrieval/repository.py) ranks eligible full-text matches for each distinct informative term under a per-term cap, combines those ranked lists into one bounded lexical arm, and uses strict full-text matching when filtering leaves no informative term. Exact quotes and numbered hyphenated identifiers use bounded literal matching; their remaining query words rank exact matches before the cap, while ordinary hyphenated words retain partial FTS. Without a reranker binding, normal uses fused results without degradation. All modes share citation hydration and complete-context admission under the runtime estimator, with a configured discovery-source cap of 36 for both fast and normal. Each mode owns one rendered-context ceiling; there is no separate learned-text or original-text budget. External evaluations independently count answer-visible context with their chosen tokenizer. Memory and Evidence compete by relevance without origin quotas; learned items and full originals retain separate result-count limits. The [core acceptance gate](acceptance.md#2-step-5-core-indexing-and-recall-gate) functionally tests both modes with Profiles disabled before L3 implementation.

Ordinary entity expansion joins stored IDs and revalidates both memberships and their current name supports using one shared eligible-fact projection. It first validates seeds, then collects an uncapped superset of facts reachable through their stored identities, name-support anchors, two outgoing causal hops when causal retrieval is enabled, and both semantic directions when full expansion is enabled. Complete current-support checks apply to those candidates before the existing ranking and branch caps; unrelated history does not require one support proof per fact. Light expansion retains its full-history nonseed eligibility gate before identity reads; graph ranking excludes seed IDs from additional candidates in every selection. Every supported name within the reachable identity set is validated, including nonseed alias anchors, before applying membership caps. Entity, causal and semantic graph paths consume facts; direct lexical/dense retrieval retains its separate passage and Insight eligibility. Paths retain selected alias quotes and source locators as metadata counted in the complete rendered context. Revoked or unpackable identity proof removes the dependent graph contribution while a separately admitted direct fact remains eligible. Fast performs no query-time entity resolver. When graph selection is off and causal retrieval is disabled, recall skips graph expansion. Enabled identity, semantic and causal paths share one graph vote without another graph or arm type; the same causal flag gates temporal discovery and path revalidation. Stored semantic neighbors already use indexed links; entity ranking uses query-vector distance within each posting list, so relative cost depends on fan-out and support checks.

Fast light expansion first checks the raw scoped fact-unit superset for a nonseed. A negative result proves its existing full-history eligibility gate is empty; a positive result runs the complete graph query unchanged. Strict fast requests without an explicit or inferred temporal window share one READ COMMITTED SQL phase after embedding and text retrieval finish. Partial, temporal and expanded-mode requests retain independent read transactions. Successfully hydrated passages are reused only within the request, with missing source-window detail fetched in its original order. The guarded trace publication checks the current active user and policy epoch under the remaining deadline and commits before returning the response. Dense ANN controls share its existing deadline setup statement before candidate retrieval. Admission timeout setup and its query are sent together when pipeline transport is supported, preserving transaction and session-lock lifetimes.

Selected Insights require every recorded L1 support revision and the eligible original chunks directly cited by that support. The [recall repository](../src/oam/retrieval/repository.py) resolves support under the existing companion limit; if that limit cannot cover all recorded supports, omit the Insight with a limit reason rather than present a subset as complete. The [source selector](../src/oam/retrieval/context.py) resolves exact citations without adjacent-turn expansion for Insights; ordinary L1 windows retain their bounded adjacent-user-turn discovery. Each Insight and its required facts/citations form one complete group, with full original bodies included only when `include.chunks` is true. Groups inherit their roots' relevance positions and are admitted atomically under the complete-rendering ceiling and per-pool item limits. Insights have no overrun exemption. Lookup and hydration failures preserve the existing recall failure contract. Final Insight revision eligibility is checked before returning; no read-time durable retry or extra model call is added.

The context renderer uses local item/source references while structured items retain complete provenance. Grouped facts inherit an original passage's time only when the complete nonempty lists match. Admission counts each complete tentative rendering, including emitted metadata and separators. The full-ID format remains available when it costs less under the same estimator.

After item and token admission, [shared context rendering](../src/oam/retrieval/context.py) associates facts with an already selected original passage only when all source/version/message/role/passage identities match and each exact support quote occurs uniquely in that passage. Returned items retain their relevance order, normalized fact text, complete citations, fact-owned time annotations and graph paths. The context presents one original passage followed by its related fact blocks, at the earliest member rank. Compact blocks use `source=[n]` to reference the selected original item; the full-ID fallback uses `Source: [passage_id]`. Other chat citations retain source revision, speaker, message ID and exact quote text; unfamiliar citation shapes keep their full JSON. A fact uses `time=source` only when its complete nonempty time evidence matches the selected original; otherwise its own time fields remain visible. Facts with additional dates or graph paths keep their structured records intact. Insights, distinct source occurrences and facts without one fully covered selected passage retain standalone blocks. Grouping adds no model call or fetch. The final rendering is recounted under the mode ceiling and explicit sole-L1 fallback, and metadata keys have a stable order so [recorded replay](../src/oam/debug/traces.py) uses the same renderer.

Partial PDF page extraction requires explicit `allow_partial: true`; default recall rejects that incomplete Resource before returning context. The [Step 6 acceptance gate](acceptance.md#3-step-6-evidence-and-joint-recall-gate) verifies bilingual originals, physical-page citations, partial PDF behavior and combined Memory/Evidence context through public HTTP.

The [canonical configuration](../configs/oam.yaml) owns both presets and deadlines. Public `POST /v1/recall` requires `user_id` and `query`, defaulting to normal when `recall_level` is omitted; the host selects fast explicitly before invoking the agent. Each pre-agent or ReAct recall gets its own operation budget, clamped by an explicit shorter caller deadline. Trusted shared-turn admission is an opt-in internal constraint, not a public body field. No automatic escalation occurs. Successful recall stores its bounded considered arms and final context under a trace ID after a final policy check; the [recorded trace reader](../src/oam/debug/traces.py) verifies every stored candidate against current eligibility before disclosing content.

[Batch and delegated recall](../src/oam/api/search.py) reuse the same [direct recall service](../src/oam/retrieval/service.py) through the [authorized HTTP runtime](../src/oam/api/runtime.py). Batch validates every caller query before dispatch, reserves deterministic shares of one selected mode total and inherits the same chunk-inclusion boolean, executes up to the configured query concurrency under one absolute deadline and returns input-ordered per-query outcomes. Delegated recall first makes at most one call through the configured [planner model role](../src/oam/models/runtime.py), validates its bounded query list, then runs those queries under the remaining deadline; a failed or invalid plan falls back to the original caller query when time remains. The [request contracts](../src/oam/contracts/search.py) keep mode and optional time controls common to both paths. Ordinary direct and batch recall remain non-generative.

The host runs fast recall before invoking the agent and supplies its evidence as initial context. During the ReAct loop, where the agent alternates reasoning and tool calls, it may request fast or normal again. OAM executes the selected preset; the agent owns subsequent queries, mode choices, and the final answer.

The [OpenClaw adapter](../integrations/openclaw/index.ts) binds one selected OpenClaw agent, defaulting to `main`, to one configured OAM user. Its owner-authorized local WebChat route covers that agent's conversational sessions, while external channels require an approved direct-conversation identity; the adapter recalls through OAM before an admitted turn and retains the completed human message after it. [Plugin setup and route limits](../integrations/openclaw/README.md) describe the operator-facing configuration.

Optional [cron capture](../integrations/openclaw/cron.ts) filters the host's scheduler reconciliation and change hooks before sending data to OAM. Only explicitly owned user tasks of the selected agent are supported; heartbeat payloads and disabled startup snapshots are excluded. Learned routine definitions require a recurring `cron` or `every` schedule and contain the name, optional description, enabled/disabled/removed state and user-relevant timing, without workflow prompts, executable payloads or transport configuration. Explicit routine disable/removal changes remain meaningful history; one-time/process/stream definitions do not become long-term routines. Routine run status, diagnostics, unsuccessful execution and host-suppressed/control-only output produce no write. Successful reports enter the ordinary interaction pipeline as explicitly eligible assistant messages containing exactly the original report text; role and run time stay in structured fields rather than collector-authored narrative. The existing extractor selects durable claims while preserving assistant attribution and source text; eligible report facts can inform Insights and explicitly refreshed Profiles under normal grounding rules. Delivery failure alone does not discard successfully generated content, and successful reports from temporary tasks can still be useful. Logs correlate accepted requests with job, operation, source and duration and explain filtering decisions. Host cancellation stops reconciliation. Filtering leaves stored history unchanged; explicitly authorized cleanup uses normal OAM lifecycle/removal APIs. The adapter has no scheduler control, database reader, automatic transcript backfill or local delivery queue, and scheduled sessions retain their existing conversational admission rules.

The [Profile input loader](../src/oam/profiles/inputs.py) selects current interaction-backed L2 Insights with cited L0 passages, plus active structured Profile Data; L1 facts remain eligible support for existing stored revisions and Insight citations, but do not independently enter new generation or its input identity; Resources and ineligible assistant text cannot support a Profile. Source event times let generated text qualify stated ages and past events. [Registered Profile Data mappings](../src/oam/profiles/resources.py) validate exact values before source activation. The [Profile service](../src/oam/profiles/service.py) compares eligible-input, canonical generation-prompt and saved-instruction identity without a model call: `GET /profile` validates supports against the collection's stored indexing generation and reads one stored content document, its references, last publication time and processing metadata; configured model or indexing-recipe changes do not prevent reading an eligible stored Profile. Refresh continues to require the configured generation; `POST /profile/refresh` returns `200` unchanged or a durable `202` receipt. It advances delayed L2 work for pending sources and waits for those jobs before generation. The bounded input selector reports how many eligible units did not reach generation; such a revision is not reported as fully current. The [canonical Profile prompt](../src/oam/profiles/prompt.txt) selects useful supports for a concise current portrait, replaces explicitly resolved corrections with the final state, preserves material unresolved qualifications and dated ages, and omits temporary test identifiers and incidental task details. Historical background and broad project activity are included only when useful, briefly. The [Profile worker](../src/oam/profiles/worker.py) generates one bounded text artifact in a JSON transport envelope, validates its cited support, appends exact Profile Data values and readable References to the default Markdown, deduplicates repeated default-format source references without changing their cited source, rejects unresolvable citation numbers, then rechecks inputs, lease and fence before publication. Successful Insight work for the active source version and generation establishes Profile input readiness, including a completed retry whose original receipt retains its failed diagnostics. Each unresolved removal repair for that source/version/generation remains a separate obligation: a newer successful repair cannot hide another repair's pending or terminal-failed work. Completing the affected repair clears its own coverage requirement; maintenance recovery does not change operation creation order. A custom authorized instruction may request another text format, including JSON; the saved instruction participates in refresh identity, and a later instruction or reset cancels conflicting active Profile work. Cancellation fences publication; a completed attempt settles even after cancellation, so its instruction can be requested again, while uncertain external outcomes still require reconciliation. Withdrawal or supersession of cited support withholds the whole free-form snapshot until refresh, while a new eligible input leaves the prior eligible document available with a non-current machine status. L2 changes never generate L3 by themselves, and Evidence-only changes do not change Profile identity. Recall dispatches directly to the [retrieval service](../src/oam/retrieval/service.py), returns query-relevant Memory and Evidence only, and uses the complete requested recall budget without reading or reserving tokens for the stored Profile. Applications independently read Profile documents through `GET /profile` and compose them with recall when needed. Profile reads and exports hydrate eligible stored support references separately from the L2-only generation inputs. Older field-based revisions are rendered by the [document renderer](../src/oam/profiles/document.py) without regeneration or persistence: it preserves stored values, qualifiers, conflicts and all eligible references, and withholds the entire document if a support cannot be resolved. Profile reads apply their independent complete-document budget and recheck source policy before returning content. Recall never reads, returns or refreshes L3; its relevant source-backed L1/L2 facts remain eligible even when they also support a Profile. Batch and planned-search results use the same retrieval-only dispatch, retaining their shared budget, authorization and deadline rules. Each separate endpoint validates its own source policy; the two responses do not promise one atomic snapshot.

## 5. Inspection and Portable Export

Learned-memory reads follow the [HTTP routes](../src/oam/api/app.py) → [runtime authorization](../src/oam/api/runtime.py) → [source inspector](../src/oam/db/inspection.py) → shared [eligibility SQL](../src/oam/db/eligibility.py) path. One public `memory_type` selector identifies `basic` (L1 facts, preferences and experiences) or `insight` (L2). It is optional on the list and required on the single learned-record detail route. The [memory contract](../src/oam/contracts/memory.py) maps those public names to internal kinds once; responses expose the public type while preserving the existing internal kind field used by the Inspector. The list filters the selected type before pagination, counts and selects a bounded page in one statement, orders by creation time and unit ID, and attaches provenance only to selected records. Typed detail reads use canonical L1/L2 identities and the same eligibility and citation assembly. Both recheck the policy epoch before returning. Offset and cursor pages observe the current collection; a captured export supplies a fixed collection when needed. L3 stays a separate read of the stored Profile and never triggers generation.

Inspection reads only current eligible L1/L2 units and Resources and Profile Data. [Source inspection](../src/oam/db/inspection.py) lists active documents and Profile Data, cited memories, current originals, Evidence abstracts or exact User Profile mappings, and operation readiness under the user's read grant; the bundled [Inspector client](../src/oam/web/app.js) uses those public routes with no browser-side policy override. Source and generated text enter the page as text, credentials stay in page memory, and the API serves same-origin assets under CSP. The Inspector displays the one stored User Profile document, safely formats parseable JSON, and submits explicit refresh instructions through the public route. The [Profile read service](../src/oam/profiles/service.py) also returns the current generation prompt from its [packaged source](../src/oam/profiles/prompt.txt); the Inspector renders it as read-only text in a collapsed panel and identifies whether a saved custom instruction supplements it.

Recorded explain, output diff and read-only replay use [trace policy validation](../src/oam/debug/traces.py): an expired or withdrawn candidate cannot be revived by a trace. [Portable export](../src/oam/exports/repository.py) captures a format-1 manifest with current source identities, L0 evidence/passages, supported L1/L2 records and their links, Resource abstracts, eligible User Profile content and reference metadata, and original descriptors. [Bounded JSONL parts](../migrations/0010_export_parts.sql) hold records without copying originals; original downloads recheck current source version, checksum and policy. Each committed indexing transaction advances the [projection epoch](../migrations/0011_projection_epoch.sql), so even a partial publication during running work invalidates an older export; source admission and policy changes also require a new export. The [offline validator](../src/oam/exports/validation.py) checks downloaded member paths, counts, lengths, hashes, source/original identity and support relationships. Downloaded copies are outside OAM's deletion control.

## 6. Runtime Topology

The [API lifespan](../src/oam/api/app.py) starts the [shared worker runner](../src/oam/workers/runner.py) by default, after configuration and database authority checks. Its dedicated thread pool executes synchronous processors without using HTTP handler threads. Dedicated deployments disable `worker.embedded_enabled` on APIs and launch `oam worker` separately; `--once` still claims at most one work unit. Each runner has up to `worker.max_tasks` task slots, ten by default, while deployment tooling selects process count. API and worker clients retain distinct database roles and foreground/background admission identities.

Shutdown first stops new claims and model dispatches, then waits up to `lease.shutdown_seconds`. Incomplete drain is reported; surviving synchronous tasks retain ownership of their clients until the final task exits. The service does not claim it can forcibly cancel an arbitrary Python thread. Readiness exposes embedded-runner health and unknown model-permit saturation while preserving the separate full-release readiness gate. PostgreSQL HA and abrupt process-loss certification remain separate release gates.

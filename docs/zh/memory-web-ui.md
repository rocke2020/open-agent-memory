# Memory Inspector 网页界面

[中文文档](README.md) · [English](../memory-web-ui.md)

## 概述

Memory Inspector 是随 OAM API 提供的用户记忆网页界面。启动 API 后，在浏览器打开 `http://127.0.0.1:17333/ui/`。它与其他客户端使用相同的公开 API 和用户权限，随同一个 API 进程提供服务。

## 1. 启动 API

先准备带 pgvector 的 PostgreSQL，以及分别用于迁移和 API 的数据库凭据。通过环境变量或 `./.env` 设置真实的 `OAM_MIGRATION_DSN` 和 `OAM_API_DSN`。CLI 从 `./.env` 补充尚未设置的变量。`.env.example` 中的值是示例。数据库凭据和认证初始化见[运维](operations.md)。在仓库根目录运行以下命令。

```bash
uv sync --locked
uv run oam migrate --config configs/oam.yaml
uv run oam api --config configs/oam.yaml --host 127.0.0.1
```

保持 API 运行，然后打开 `http://127.0.0.1:17333/ui/`。新建本地 `dev` 数据库时，在迁移前确保环境变量和 `./.env` 中的 `OAM_ROOT_API_KEY` 和 `OAM_BOOTSTRAP_OUTPUT` 都未设置。已有密钥认证的数据库会继续使用密钥认证。如果 17333 端口已被占用，可使用其他 `--port`，并相应修改浏览器 URL。

## 2. 连接到你的记忆

在表单中填写同一记忆集合的租户、用户 ID 和可选 API 凭据。

| 认证模式 | 租户和用户 ID | API 凭据 |
| --- | --- | --- |
| 本地 `dev` | 活跃租户，通常是 `default`，以及要查看的用户 ID | 留空。此模式只允许环回监听，访问者之间没有隐私隔离 |
| `api_key` | 用户密钥所绑定的租户和用户 ID | 填写**用户密钥**。管理员密钥仅用于管理 |
| 本地 `trusted` | 活跃租户和声明的用户 ID | 留空。界面通过本地断言请求头发送所填身份 |
| 非本地 `trusted` | 由完成认证的网关提供身份 | 通过网关打开页面。网关应重写身份请求头并在服务端提供管理员授权，浏览器无需管理员密钥 |

在 `api_key` 模式下，租户管理员通过 `POST /v1/users` 创建用户，并收到仅返回一次的首个用户密钥。如尚未拿到用户密钥，请联系管理员。见 [HTTP 管理 API](api.md#2-管理)。点击 **Connect（连接）** 加载该用户当前的记忆和资源。凭据仅保留在页面内存中，退出连接或刷新页面会清除。

## 3. 使用各视图

顶部栏包含 OAM 标识、当前集合、语言选项和 GitHub 仓库链接。使用侧栏切换视图，窄屏幕上会变为横向导航。语言菜单可选择英语、西班牙语、法语、德语、葡萄牙语、日语、韩语、简体中文或繁体中文。页面首次加载时选择浏览器优先提供且受支持的语言，并记住显式选择。切换语言会更新控件、无障碍名称、状态信息和日期时间显示，并保留当前连接、所选项、表单输入和召回结果。记忆、来源消息和召回内容保留原有语言。

**Memories（记忆）** 按添加时间倒序列出当前事实和洞察，列表和详情显示洞察的子类型，可检查支持它的原始消息。**User Profile（用户画像）** 提供一个只读文档。默认 Markdown 安全呈现标题和粗体，编号引用、来源日期及标识位于折叠的引用详情面板。可解析的自定义 JSON 格式化显示，其他格式安全地按文本显示。页面显示最近记录的画像刷新时间。可选自定义指令控制画像的呈现方式，并随版本显示。选择 **Use default instructions（使用默认指令）** 恢复默认。**Create/Refresh User Profile（创建或刷新用户画像）** 会复用未变化的内容，或返回一个操作来准备未完成的记忆输入、按现有规则重试可恢复的失败输入一次，并处理待定洞察，再生成文档。重试额度耗尽或外部结果不明时需要运维处理。状态显示洞察或初始处理失败数，以及超出画像输入上限的合格项目数。**Resources（资源）** 经由 `/resources` 创建、修订、查看和删除文档原件及段落。删除来源会立即排除所有版本及依赖输出，之后由独立操作从活跃存储中清除。

进入记忆、洞察和资源页面时，界面会自动打开首个可用项。刷新或加载更多时，只要原选择仍在列表内就会保留。空集合显示空状态。**Entities（实体）** 默认显示列表，可以切到 **Relationships（关系）** 浏览连接。

**Retrieve（召回）** 提供 Fast、Normal 和 Deep，完整上下文默认上限分别为 8,000、16,000 和 24,000 tokens。界面初始选中 Fast，并在每次请求中显式发送所选模式。服务返还该模式下的证据与引用。

每条洞察都有用于概括长期主题的简洁标题，列表标题下显示子类型，详情标题也使用该名称。随着正文新增事件或状态，标题通常保持稳定。证据改变或澄清主题时可更新标题。完整正文、规范 ID、版本和支持来源始终在详情中。旧记录使用已保存的主题标签或长度受限的正文预览作为标题。浏览操作只读取数据。

选中记忆单元或洞察可核对带类型的规范 ID、版本、内容、来源及依赖洞察，再执行 **Remove Memory Unit（移除记忆单元）** 或 **Remove Insight（移除洞察）**。操作仅提交该 ID，保留来源，并在排除后刷新列表。回执分别报告清理与相关整合操作。通过操作状态跟踪后续工作。移除学习条目后，受影响的存储画像内容在显式刷新前会停止显示。

新集合可能为空。API 可以独立提供网页。索引会话与资源、生成变化后的用户画像需要工作进程、队列及内容 DSN，以及配置好的模型角色。若使用独立工作进程，在另一个终端运行 `uv run oam worker --config configs/oam.yaml`。默认 YAML 不含模型端点或凭据。见[模型配置](operations.md#1-配置)。

顶部栏显示已连接范围及活跃集合最近一次记录的更新时间，以浏览器本地时间显示。悬停查看完整日期和时间。记忆和召回视图使用当前合格记忆的最新发布时间。洞察使用当前合格洞察的最新发布时间。用户画像使用所记录的发布时间。资源使用当前活跃修订中最新的接收时间。集合时间涵盖所有分页，独立于查询结果，无时间可显示时会隐藏。该时间反映当前内容，删除历史和索引完成情况可通过其他记录查询。结构化画像资料通过 API 上传、修订、下载和删除。见[画像资料与刷新](api.md#画像资料与刷新)。用户画像视图简要显示新鲜度状态。若引用仍合格，旧版字段式画像也可直接显示。旧版本缺少发布时间时显示 **Profile update time not recorded**。没有可读画像时，使用 **Create/Refresh User Profile** 重建。如果超过预览 token 预算，可提高或清除预览限制。画像契约不存储处理截止日期，界面也不展示该字段。

## 4. 排查页面或连接错误

页面无法打开时，检查选定主机和端口上的 API 是否仍在运行，也可调用 `GET /health/live`。连接失败时核对租户与用户、密钥类型、授权以及 API 数据库连接。连接操作会加载实际记忆与资源，可据此验证个人数据访问。接收后仍未就绪或未显示时，检查原操作状态和工作进程。数据库与模式、模型配置、容量及适用的工作进程检查通过时，`GET /health/ready` 返回 `200`，失败时返回 `503` 及原因。就绪检查不调用模型，实际能力需通过授权的数据操作验证。

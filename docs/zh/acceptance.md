# Open Agent Memory 验收标准

[English](../acceptance.md) · 简体中文

## 概述

发布声明需要通过真实的公开路径取得可检出错误的证据。单元测试验证确定性策略，集成测试验证 PostgreSQL 和提供商边界，小规模、经授权的端到端运行验证可供检查的产物。每一层分别提供相应证据。

## 1. 第 1–4 步 基础验收

基础验收要求软件包干净且目标明确、公开文档自包含、配置严谨封闭、迁移和 RLS 有版本管理，并覆盖凭据与初始化、持久化操作和任务认领、有界的本地解析器、模型能力探针、OpenAPI 数据类型、操作接口、一致性测试用例及同源 Inspector 外壳。索引和检索由后续环节验收。

仓库记录了基础功能的确定性单元和契约测试，以及 PostgreSQL 集成测试。只有同时设置 `OAM_TEST_POSTGRES_DSN` 和 `OAM_TEST_POSTGRES_ISOLATED=1` 来指定明确隔离的数据库时，才运行集成测试。初始化测试会在该隔离服务上单独创建数据库并保留用于诊断，测试操作者须具备建库权限。现有基础证据包含真实 PostgreSQL 18 的运行结果。生产部署和副本恢复需要独立验收。

认证验收应在隔离环境中通过 API 和 SQL 覆盖以下组合。针对 `api_key` 验证拒绝根密钥访问个人数据、同用户和跨用户密钥。针对 `dev` 验证无根密钥时在回环地址启动、拒绝降级已设置密钥的数据库。针对 `trusted` 验证本地断言、用户首次注册、租户或用户不一致、非本地场景的根密钥证明，以及仅根密钥可执行的管理操作。对 v0.0.1，应在隔离的本地容器网络中模拟非本地可信边界。真实网关应认证合成调用方，替换伪造的身份请求头，并阻止调用方网络直连应用监听端口。记录为本地模拟，外部生产网关和身份提供商尚未验证。v0.0.1 的范围不含 OIDC 和 LDAP。

带日期的命令、产物探针和明确的排除范围见[第 1–4 步基础证据（英文）](../foundation-evidence.md)。

## 2. 第 5 步 核心索引与召回验收

本阶段独立验证会话索引和召回，资源和 L3 用户画像由各自环节验证。公开路径必须提交符合条件的会话及回执，生成有来源支撑的 L0/L1/L2，并通过 Fast、Normal、Deep 的直接召回返回带引用的记忆。先验证公开 Fast 路径，再在同一验收阶段完成 Normal 和 Deep。

三种模式共用同一条流水线。若没有显式排名时间窗口，在检索候选前解析受支持的查询日期。标准 Fast 配置融合向量检索、结合全文和严格字面匹配的一条 BM25 排名词法通道，以及可选的时间通道。各模式独立选择实体和语义图扩展。三种模式共用因果遍历策略，将启用的图结果合并成一个可选通道。默认关闭的个人证据通道提供另一条排名列表，由当前偏好和经历支撑的用户原文组成。标准 Normal 和 Deep 配置的图通道权重为 0.1，其他已执行通道为 1.0。Fast 的已执行通道等权。通过公开 HTTP 验证 `LAB-204` 不会匹配 `LAB-2045`，显式匹配 `"morning shift"` 时须连续出现。含编号或带引号短语的混合查询在应用上限前，须按其余有信息量的词对严格匹配排名。只有被过滤的功能词构成的普通名称仍须执行严格词法检索。检查融合输入，确保由全文和字面匹配共同命中的单元仅有一票词法贡献，且没有 `anchors` 通道进入 RRF。跨主题和查询表述核对有界部分匹配，确认其不依赖特定主题词汇，并在三种回答上下文的配置项数和估算 token 预算内核对来源证据。验证有界的实体与语义链接，以及可独立启用的两跳因果路径。关闭因果须保留时间链接和日期筛选，关闭实体和语义图扩展时仍可执行配置启用的纯因果检索。通过实际召回上下文验证四种组合，确认禁用的 SQL 分支在候选限额前省略。通过公开 HTTP 验证英文、中文及受支持的日文绝对和相对时间表达，显式窗口优先、歧义日期产生诊断且保留普通召回、时区边界、窗口外直接证据仍可参与，以及仅由图发现的时间证据。验证 Normal 和 Deep 在配置重排器时调用它，在未配置时无需降级即可仅使用 RRF。只为 Normal 配置重排器时，Fast 须使用融合后的相关性且不调用模型打分。必须实际生成、持久保存且可召回一条具有经过验证的描述性子类型的 L2 洞察，核对精确的 L1 到 L0 支撑、增量综合，并区分有效的 `no_insight` 和格式错误、空输出、拒答或失败。任何召回模式都不得生成内容，均须执行请求和共享轮次的时限并报告失败或覆盖不完整。所有模式都须通过公开 API 验证。仍须逐步执行 LME-6、LME-30 和 LME-60，功能探针与基准验收分别执行。

通过实际 Fast 召回验证配置的局部证据策略。配置的向量种子前缀中的直接用户事实及其精确用户原文可以保留同一轮交互中部分匹配的助手回复，同源后续无关轮次不能复用该支撑。保留直接向量命中、严格词法或字面命中、配置启用的图结果、资源结果及完整洞察支撑。验证逐条引用配对原文、来源版本隔离、筛选支撑证据前向量通道的原始顺序，以及整句查询和逐词排名两种独立词法策略。验证向量检索不可用时仍可走降级的词法召回。验证没有提取出单独事实的相邻用户原文，在其相关事实之后进入回答上下文，计入完整正文且不伪造引用。超出预算的相邻正文须保留原有事实与必需支撑。使用有独立匹配用户事实的确切来源跨主题验证，在相邻窗口之外有界恢复更早的用户原文。弱词法匹配事实、仅含助手的来源和其他来源版本均不能授权这项恢复。恢复的原文不能授权助手回复或继续扩展。必需的归属支撑优先于补充原文。若未纳入归属事实，补充原文仍可在普通候选位置参与。只有纳入完整原文后渲染结果仍满足预算，才可用它升级先前摘录。超预算时保留摘录和必需支撑。同时检查最终覆盖、被挤出的靠后证据、完整原文计数和无关上下文。在标准 Fast 的候选、融合、来源种子和结果上限 64/128/36/88 下保留原始查询的 embedding、图配置和时限，并多次通过完整 HTTP 路径测量延迟与上下文相关性。

验证完整渲染的默认预算分别为 Fast 8,000、Normal 16,000、Deep 24,000 token，并对三种模式分别验证 2,048 token 限额。省略 `include`、传入空的 `include` 或使用 `chunks: true` 时都须纳入符合条件的完整正文。`chunks: false` 严格省略所有完整正文条目或区块，包括洞察的原文，同时保留符合条件的学习条目、全部必需支撑事实和真实引用。拒绝 null、非布尔值、旧的段落选项对象及已移除的请求预算。重算完整渲染的 token 数，包括元数据、重复引用和分隔符。验证整组省略且不裁剪、跳过单个过大的 L1 事实后仍能纳入后续较小组、共享来源去重、完整洞察支撑和各结果池的条数限制。独立排名且能提供答案的原文即使无提取事实，或对应学习证据组过大，也须保留相关性位置，并在预算内保留完整正文。验证不合格的候选不会在限额前占用合格的来源代表名额。双查询的批量请求共享一个模式的总预算，规划召回也遵循同一布尔值和模式契约。检查最终返回的证据和引用，候选出现及计数只作为过程证据。

固定用例只建立一次索引。对同一合格索引和查询集比较 Fast、Normal 和 Deep，记录对比使用的各模式上下文上限并禁用 L3。预先确定应返回的事实、段落及支撑引用，包括图通道发现的证据，使检查可以检出缺失。保留请求、响应、用例和配置标识。汇报一次索引用量，以及各模式相对预期证据的检索质量、上下文 token、召回用量、延迟和失败。优先衡量真实使用中三种模式的质量和延迟。最终答案准确率需由独立外部评估器衡量。

## 3. 第 6 步 证据与联合召回验收

使用公开的[中英双语合成用例（英文）](../../conformance/fixtures/medical/bilingual/README.md)。用例包括内容等价的中英文 HTML、原生文本 PDF、扫描 PDF 和 PNG 报告，以及包含多行的三页纯文本过敏报告。通过公开 HTTP 保存每份原件，验证已存字节和清单哈希，提取详细段落，生成摘要并汇报实测视觉用量。原生 PDF 页须保留物理页引用。过敏报告每页均须完成索引且不调用视觉模型。扫描页和图片须使用提取绑定的视觉能力，引用页或图片，有区域信息时验证该区域。带原生文字的矢量表格须请求视觉结构信息并保留原生措辞。后续 PDF 页失败时，只有已完成的细节可通过显式 `allow_partial: true` 检索。摘要失败须保留已索引的详情。报告及其摘要均不得生成 L1/L2。

单独保存符合条件的会话，再对同一联合索引执行 Fast、Normal 和 Deep。检查选中的上下文同时包含记忆和证据，共享完整上下文 token 上限，并对学习条目和完整正文分别限制数量。核对引用、来源链、共享时限、召回生成调用为零，以及根据报告生成的助手回答被排除在学习之外。隔离 PostgreSQL 的确定性测试验证路由和 API 契约。模型质量验收还要求经授权的真实运行，通过文档视觉和多语言 embedding 验证实际中英文提取和跨语言召回。保存请求、回执、引用、用量、用例和配置标识作为可核查的证据。

对 URL 证据，分别用隔离的确定性 HTML、PDF 和图片 URL 跑通公开保存、Worker 索引和带引用的召回，对比已存字节及摘要值与获取的原件。验证获取前授权、相同幂等键复用且不重复获取、获取失败后允许重试、拒绝非公开 DNS 及字面 IP、固定使用已校验地址、拒绝重定向、有界传输、拒绝类型不匹配和隐去 URL 查询参数中的令牌。声明为 HTML 且返回 200 的 HTML 页面按原样接收，调用方需检查其内容。发布前，不受信任的本地 PDF 解析和渲染须在有界子进程中运行，子进程卡住或崩溃时，持久任务 Worker 不得随之卡住或崩溃。

## 4. 第 7 步 用户画像验收

第 7 步在已评估的核心功能上实现 L3 用户画像。它保存一份正文文档以及单独的 References，输入包括符合条件的 L0/L1/L2 和显式画像数据。关闭自动触发器时，输入变化只标记画像非最新而不生成。验证 `GET` 只读、输入变化后异步刷新，以及无变化时返回 `200` 并零调用复用。确认画像排除报告衍生内容，刷新失败后仍保留符合条件的上一份文档。旧版按字段组织的修订仍可兼容读取，当前存储契约使用文档。

Agent 集成场景从宿主调用 Agent 前执行一次 Fast 召回开始。在 ReAct 循环中，Agent 可再次请求 Fast、Normal 或 Deep。HTTP 契约须保留选择的模式，并始终由调用方决定是否再次查询和使用何种模式。

LongMemEval 筛查记录所选召回模式、已索引的历史和评测标识。最终只测 Fast 的结果与历史模式对比分别记录。汇报准确率、上下文 token、延迟及仅计生成的索引用量。v0.0.1 未设发布基准的数值门槛。

直接、批量和规划召回均须独立于 L3。验证拒绝已移除的画像选择选项，不访问或附加已存文档，且保留完整的检索预算和相关底层事实。在存在已存画像时，使用一旦调用就报错的画像读取器验证召回。随后禁用画像功能，重复验证检索，同时确认显式读取或刷新画像均报告功能不可用。独立读取画像，请求一次输入变化后的刷新，观察操作成功后重新读取更新文档。保留零生成读取、无变化零调用刷新、超出预算时省略整份文档和来源资格规则。

[画像策略及自定义生成](profiles.md)还要求验证 UTC cron 边界、独立的完整重建时钟、合并触发造成的间隔延迟、保留活跃显式任务、失败暂停与恢复，以及用户与租户隔离。验证临时 Markdown 和 JSON 生成结果带有当前引用，且不更改已存画像或操作状态，不记录内容日志或缓存。分别记录确定性调度测试和从实际计时器触发到发布的证据，并报告跳过的数据库和运行时用例。

## 5. 第 8 步 来源与 Inspector 验收

第 8.2 步的来源生命周期独立于 L3 用户画像。通过公开 HTTP 在隔离用户集合中保存两个独立来源，使用 `If-Match` 修订文本及上传或 URL 证据，在开销较大的输入处理前拒绝过期版本。删除会话来源和经修订的资源，证明它们的所有版本立即从 L0/L1/L2、证据段落和摘要、召回、检查、跟踪及导出中消失，独立来源仍可用。重复删除须返回已有清理回执。持有过期隔离令牌或旧来源版本的 Worker 不得重新发布内容。执行清理认领，分别检查终态操作、活动存储中的原件和衍生数据及服务端保留的导出分片，并验证即时排除回执。串行集成验收须在第 7 步完成后才检查删除对用户画像的传播。

第 8.3 步需要验证经授权的 L1/L2 支撑和资源原件与定位信息视图、已记录轨迹解释、按当前策略回放及历史输出差异，以及下载后能通过清单和所有声明成员的离线验证的导出。挑战用例包括已删除的候选、导出策略变化、校验和篡改、支撑缺失、根密钥、其他用户密钥和请求执行中的策略变化。浏览器验收覆盖同一公开路由、将来源 HTML 作为无执行能力的文本渲染、精确删除目标确认、操作就绪状态、凭据只存在页面内存、退出登录、焦点和导航、窄屏和系统明暗偏好。可用的外壳或本地确定性探针仅覆盖相应环节，真实模型质量和发布就绪状态需单独验证。

## 6. 完整发布验收

v0.0.1 在通过核心、证据、L3 验收后，继续验证基于 Fast/Normal 核心的批量和规划召回、来源修订与删除、解释及差异和历史回放、可移植导出、浏览器与 API 一致性、多 API 和 Worker 恢复以及留存的基准证据。部署验收范围为 macOS 上的隔离进程或 Docker/Compose 容器模拟，包含两个 API 副本、两个 Worker、共享 PostgreSQL、应用实例丢失与重启、滚动替换及十个并发请求。物理多主机操作、宿主内核故障和跨主机网络尚未验证，且不属于首次发布验收前置条件。在人工审核内容前，为 Linux AMD64 和 ARM64 构建候选镜像，按不可变镜像身份在本地运行完整矩阵，并标明原生和模拟环境的检查。

发布评估在 LME-60 之外还要求 BEAM 10M 完整性检查。使用公开 OAM Normal 召回，按冻结的答案生成及评分细则协议保留全部十段官方完整会话及全部 200 道题的最终结果。保存输入、评估器、产品、模型和配置标识，以及来源日期和获准填补的一处日期。最终协议使用 `low` 提取推理和仅 L1 索引，无画像，评分所用的检索上下文不含 L2。在新隔离范围继续运行时关闭洞察，并验证零洞察、零整合任务。复用首个会话在启用 L2 前保存的上下文。保持冻结的 Normal 上下文设置，独立统计确切的回答上下文，不使用公开请求的预算覆盖。另行验证 L2 和用户画像的正向产品路径，已完成的评测继续复用。

每段历史的来源操作须成功且满足第一阶段就绪条件。要求恰好有 200 个预期的唯一题目结果，独立核验评分细则算术、空上下文和空分数计数、按类别划分的质量、提交给回答模型的确切上下文及 token、索引时间、仅计生成的索引 token、召回延迟及失败。生成性能比较排除 embedding token，并披露有效的部分提取、缺失用量、失败尝试和中止的 L2 实验。检查答错或有争议的最终上下文及代表性的正确案例。完整验收须覆盖全部用例且完成操作和模型步骤，不能用失败操作、终止的模型失败、降级检索、对话前缀或仅一段会话的诊断满足。v0.0.1 发布不要求最低准确率、提供商等价或相对效率数值，缺少匹配条件的对比仍须作为限制披露。此次 Normal 评测只衡量该模式，Fast、L2、用户画像和证据能力各自需要独立验证。

## 7. 证据规则

需要可见内容的 LLM 探针至少允许 1,024 个输出 token，并拒绝由长度限制终止、空白或格式错误以及只有推理的输出。Embedding 须为有限数且维度一致。浏览器界面或静态文件存在、健康状态、非空输出、模式兼容和旧测试通过，各自只证明对应检查范围。

默认测试使用确定性模拟和隔离的临时数据库。必要的提供商探针遵循已有授权并记录用量。破坏性数据库操作需要对确切目标的授权。恢复模拟可停止或重启本次任务拥有的本地进程，不接触持久个人数据。用户负责最终内容的人工审阅，以及将仓库由私有改为公开。本地就绪和 npm 登录不构成授权。只有得到明确发布授权后才发布镜像或软件包、推送触发发布，并执行公开产物检查。本地候选版本检查仅提供本地证据。

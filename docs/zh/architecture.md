# Open Agent Memory 架构

[English](../architecture.md) · 简体中文

## 概述

OAM 使用统一、受策略约束的数据层。不可变的来源证据是权威数据，记忆和画像是可重建的派生表示（投影），召回组装大小受限的上下文，无需生成答案。PostgreSQL 管理内容、策略、任务及应用副本恢复，替换 API 和 Worker 进程时仍保留已接收输入。按用户隔离的保存与召回核心、来源生命周期、记录检查与可移植导出、用户画像确定性路径已通过功能验证。用户画像真实模型质量、部署恢复和基准性能分别验收。

来源段落的切分与装填使用 `auto` 或显式覆盖选定的 embedding 计数器。画像继续使用通用配置所选的计数器，提取估算沿用有版本的 Unicode 规则。运行时召回使用缓存的 `o200k_base` 对每份完整渲染上下文计数。[切分器](../../src/oam/indexing/chunker.py)对完整候选子串计数，保留原文的字符范围，续跑时保持已发布的段落边界。纯空白范围可不纳入可搜索段落，已接收的 L0 来源字节完整保留。配置变更不会改变已有用户命名空间，续跑时保留先前发布的段落边界，并在输入一致时复用检查点。

[Embedding 准入边界](../../src/oam/models/embedding_inputs.py)在发出 HTTP 请求前准备每个最终输入（包括带前缀的召回查询），并验证调用方提交的完整批次。绑定的 tokenizer、单项及请求限额均默认使用 `auto`，由同一实现按确切且受支持的模型名解析。单个 embedding 输入过大时，保留适配所选计数器限制的 Unicode 前缀，计数含特殊 token，并记录不含内容的警告。已保存的来源、事实和查询仍是完整文本。找不到满足限额的非空前缀，或超过请求总量或项数限制时，整批在 HTTP 发送前失败。运行时和 CLI 预检共享此逻辑，保持原批次并统一发送。未知请求限额继续标为未知，选定词表本身无法证明与服务端一致。本地准备失败只结算对应检查点阶段，其他未结算工作保留。[配置](../../configs/oam.yaml)决定选择，[运维指南](operations.md)列出确切的自动配置、覆盖方式和兼容限制。打包的 Qwen 资源可离线加载，显式本地 tokenizer 资源使用配置指定的环境变量名及内容摘要标识。

## 1. 权威与隔离

[Memory Inspector](../../src/oam/web/app.js)走与其他客户端相同的认证 HTTP 路径，从混合或仅 L2 记忆列表选取规范化的类型化 ID，查看有来源支撑的实体和已存关联，再打开相关记忆或支撑事实。[详情组装](../../src/oam/db/inspection.py)委托[关联检查](../../src/oam/db/inspection_relationships.py)，复用[实体支撑证据的当前资格判断](../../src/oam/db/entity_eligibility.py)，返回前核对来源策略。检查只显示已存关联，无需推断新的实体或因果边。召回界面通过 `/v1/recall` 发送完整用户查询及所选召回模式，再渲染证据列表与上下文，无需生成答案。

租户是组织的安全边界。每对 `(tenant_id, user_id)` 标识一个个人记忆集合。在访问内容前，系统用配置选定的认证模式确定这两个值。`api_key` 从用户密钥获取，`trusted` 接受经验证的上游断言，仅限回环地址的 `dev` 接受本地断言且不提供隐私隔离。`api_key` 模式下根密钥无权选择个人内容，非本地 `trusted` 模式下持根密钥的可信上游可断言用户。内容身份、支撑链接、操作、尝试、轨迹和幂等键都属于这对标识。公开契约只使用这两个集合选择字段。实现依次涉及[认证模式准入](../../src/oam/api/app.py)、[请求身份](../../src/oam/auth/modes.py)和[数据库权限](../../src/oam/api/runtime.py)。

除显式 SQL 条件外，强制执行 PostgreSQL 行级安全（RLS）作为第二道边界。迁移凭据与 API、Worker 角色分离，后两者既非所有者亦非超级用户，且没有 `BYPASSRLS`。Worker 先通过权限狭窄的队列角色认领元数据，再在独立内容事务中绑定经授权的租户及用户。[用户身份迁移](../../migrations/0004_user_identity.sql)重命名集合的键和策略，同时保留既存个人集合。[密钥权限迁移](../../migrations/0005_personal_key_authority.sql)使旧管理员或跨用户授权丧失效力，补录所有者主体且不删除内容。[断言用户迁移](../../migrations/0006_asserted_user.sql)仅在活跃租户中注册首次出现的用户，并使无根密钥的自动模式选择在重启后保持稳定。[事务上下文](../../src/oam/db/context.py)绑定 `oam.user_id`。管理员调用 `POST /v1/users` 可创建集合和首个用户密钥，创建者不会因此获得内容权限。

运维人员在启动应用副本前执行迁移。无根密钥初始化会创建不带凭据的 `default` 租户，带密钥初始化会创建管理员且只存储根密钥摘要。系统生成的根密钥交付至仅运维人员可读的新文件，运维人员自行提供的密钥已为其所知。生成密钥的交付中断后，须显式恢复同一个管理员。运行时的凭据管理根据所提供密钥的摘要确认操作者，签发新的并行密钥以轮换，且只能撤销同一租户的凭据。迁移凭据专供迁移进程。[初始化](../../src/oam/auth/bootstrap.py)、[认证](../../src/oam/auth/repository.py)及 [HTTP 运行时组装](../../src/oam/api/runtime.py)分别实现这些边界。

[配置加载器](../../src/oam/config.py)校验标准 YAML，叠加显式选择的部分运维配置，再固定解析值。[HTTP 准入](../../src/oam/api/admission.py)依据同一组值确定请求限额和能力，请求模式只约束结构，数值限额仍来自配置。就绪状态在固定边界内核查数据库及模式、模型配置、容量和适用的 Worker。发布验收和模型质量需独立验证。

## 2. 证据、投影与资源

符合条件的交互进入 L0，并可生成 L1。相关的 L1 记录可生成有证据支撑的 L2 洞察，具有一个描述性子类型。可用值为 `preferences`、`patterns`、`projects`、`relationships`、`experiences` 或 `general_insights`。这些标签共享同一综合和支撑流程，不影响标识或排名。生成事实、洞察和用户画像时称当事人为「用户」，无需推断性别，并原样保留确切引用。显式刷新用户画像会提前运行符合条件的延迟 L2 任务，等待其结算，再[选择符合条件的 L1 事实、L2 洞察及确切画像数据](../../src/oam/profiles/inputs.py)以发布 L3。L1 事实可以独立支撑画像陈述，L0 段落提供引用依据，L1 变化参与判断生成输入是否改变。[画像提示词](../../src/oam/profiles/prompt.txt)落实此边界。资源会产生详细段落和派生摘要，其输出仅用于资源检索，不输入 L1、L2 或 L3。

[提取提示词选择](../../src/oam/indexing/extraction.py)将实体、别名、时间以及状态更新提取保留在通用提示词中。`index.enable_causal_graph: false` 为默认值，设为 `true` 时追加[公共示例的因果指令](../../src/oam/indexing/extraction-causal-suffix.txt)。单段提取、分组提取、参考事实准入和溢出重试均使用同一有效提示词。禁用因果时，校验会移除意外返回的因果字段，并保留其余有支撑的事实。此索引选项独立于查询时的因果设置，参与[索引配方标识](../../src/oam/indexing/identity.py)。

[洞察综合](../../src/oam/indexing/extraction.py)可提供简短且有支撑的主题、项目或目的标签，以供语义检索。[增量整合](../../src/oam/indexing/consolidation.py)及[支撑移除修复](../../src/oam/governance/repair.py)有标签时将标签向量化，否则将整篇综合文本向量化。已存且在回答上下文中可见的洞察、词法检索文本、支撑 ID 与引用保留完整的有据陈述、测量值和行动状态。每条洞察仍只有一个语义向量，在每个检索通道中只有一个候选项，L1 向量保持原样。标签属于内部索引元数据。每条洞察的定位信息另含一个最多 120 个字符的非空白标题，用于检查、可移植导出及 Inspector 标题。CREATE 或 UPDATE 提供标题，只追加支撑的 KEEP_TEXT 保留标题，移除修复从剩余证据派生标题。迁移 0036 为原有当前记录补齐标题，无需生成或重建索引，读取时继续兼容旧版预览回退。只有启用洞察时，[索引标识](../../src/oam/indexing/identity.py)才包含增量配方及其生成限额。现有集合不会自动重标或重建。

常规 L2 任务随来源增量维护知识。[整合器](../../src/oam/indexing/consolidation.py)以最早待处理种子为中心，按语义链接的最低相似度配置对未审查的相关事实分组，再交替选取符合条件的既有洞察向量匹配和词法匹配。相似度只用于推荐候选，[增量综合规则](../../src/oam/indexing/incremental-insight-prompt.txt)要求有身份支撑才能 UPDATE。每次请求在完整输入预算内纳入获准的完整目标正文及有界的历史 L1 证据。标准限额是八个新种子、八份目标正文、共 64 条事实及 64,000 个完成 token（含提供商推理 token）。请求超限时缩小种子组，保留已纳入目标的正文，查询失败时显式失败。每个提交的种子恰有一个模型决定，分别为 UPDATE、CREATE、KEEP_TEXT 或 NO_INSIGHT，延期种子保持未完成。共享模型输入包含事实 ID、文本、已知角色及陈述时间、可用的时间注释、种子 ID，以及已纳入的完整目标文本和所有非空检索标签。缺少的可选值省略。来源引用、目标修订、完整支撑历史、子类型和向量保留在内部。标签属派生上下文，独立支撑来自事实。

UPDATE 保留洞察 ID，推进修订，并合并原有合格支撑和提供的相关支撑。CREATE 的标识在兼容重试间保持稳定。模型调用及 embedding 调用均完成后，文本、支撑、当前搜索投影和种子完成状态在同一个[受保护事务](../../src/oam/indexing/store.py)中发布。系统重新核对预期修订、直接移除及每项保留的支撑，因此失败或过期更新保留上一个合格修订。Embedding 输入没有变化时复用向量，仅追加支撑的修订亦如此。既有措辞仍准确时，模型返回 KEEP_TEXT 并选择所提供的支撑。后端绑定截取的修订，将决定解析为只改支撑的 UPDATE（保留原文、标签、子类型及向量），或在所有选中支撑已经保留时解析为内部 NO_CHANGE。NO_CHANGE 无需新增修订或 embedding，NO_INSIGHT 记录已审查并保留 L1。重试时保留已完成组，未完成任务由现有的有界 Worker 重试机制处理。L2 输入变化后，已存画像标为非最新且不生成 L3。

装填与发送共享相同的精简输入表示及完整消息预算。检查点同时绑定这份表示、截取的完整事实与目标状态、配置、generation 和[模型边界配方](../../src/oam/indexing/identity.py)。即使模型可见文本相同，内部输入变化仍会使检查点无法复用。[支撑移除修复](../../src/oam/governance/repair.py)从每个仍合格的支撑事实加载现有时间注释，并使用同一事实表示。独立的单次综合请求须先装下完整的剩余支撑集合，修复流程无增量目标动作和 KEEP_TEXT。原有移除、修订及发布保护继续生效。

```text
eligible interactions -> L0 -> L1 -> supported L2 --+
                                                   +-> requested L3
explicit Profile Data      --------------------------+
stored L3 -> independent GET /profile -> caller-owned personalization
query -> authorized retrieval + stored entity hints -> relevant L0/L1/L2 + Evidence -> bounded recall
stored L3 ------------------------------------------------------X-> recall

text/HTML/PDF/image upload or HTTPS URL -> immutable original -> passages + abstract -> joint recall
Resource ----------------------------------------------X-> L1/L2/L3
```

每个生成的陈述保留指向不可变来源版本和定位信息的支撑。来源修订或删除会先改变内容资格，再由响应或 Worker 发布核对旧派生数据是否仍可使用。

[运行时提示词索引](prompts.md)链接打包的文本文件，用于事实提取、洞察综合、默认用户画像生成、资源读取、查询规划和部署预检。每份编写的指令由运行时中的一个文本文件管理，使用方单独组装请求专有输入。

[资源解析器](../../src/oam/resources/)保留 PDF 页原生文本，并渲染扫描页及含大图或矢量表格的文本页以便[视觉提取](../../src/oam/workers/index_source.py)，在信息可用时引用 PDF 物理页或图片区域。文本事实提取和视觉文档提取使用同一个 `extraction` 模型绑定，须兼有文本和视觉能力。[模型适配器](../../src/oam/models/runtime.py)将有界的图片字节发送至该绑定，[索引](../../src/oam/indexing/store.py)记录实测用量。详细文本段落进入现有的 embedding 和词法索引，搜索向量基于提取文本。 `embedding` 角色选择单独的绑定，运行时校验和数据库初始化统一由 `index.embedding_dimensions` 决定向量维度。若后续 PDF 页失败，已完成段落标为部分覆盖。摘要失败后保留详细段落。

[标准配置](../../configs/oam.yaml)使用 `models.vlm` 管理全服务共享的一个 VLM 模型及选定的 Chat、Responses 或 Messages 协议，并声明 `text` 和 `vision` 能力。各生成角色只在 `models.reasoning_effort` 选择 `none/low/high/max` 推理档位，值为 null 时禁用该角色。[绑定解析](../../src/oam/models/bindings.py)固定共享模型、端点、凭据及角色档位，然后应用所选协议和推理模式。[运行时生成](../../src/oam/models/runtime.py)与[能力预检](../../src/oam/models/client.py)使用相同的请求转换与响应验证。Embedding 和可选的重排保留各自的非生成式定义。[索引配置](../../src/oam/indexing/identity.py)变化后仍能读取已有合格记录。来源范围内的检查点在输入匹配时复用已完成工作。

[PDF 子进程边界](../../src/oam/resources/pdf_isolated.py)将本地解析、页面检查和渲染放在持久任务 Worker 进程之外，超时与传输限额由父进程执行。模型调用和发布由 Worker 自己完成。子进程崩溃或超时会将资源标为失败，且不会在 Worker 进程内重试解析。

[图片处理](../../src/oam/resources/images.py)在完整解码前验证原件的格式、字节数及输入像素硬上限。当图片超过 `resource.max_pixels_per_image` 时，只缩小视觉输入副本，保留宽高比、显示方向和透明度。较小图片保留确切字节。[PDF 渲染器](../../src/oam/resources/pdf.py)会先降低渲染比例，再为原本会超限的页面分配位图，并报告实际位图像素。总像素限制 `resource.max_total_pixels` 使用原图片像素或渲染后的 PDF 像素。达到总限额时拒绝继续处理，后续页无需按任意剩余量缩放。原件及归一化引用区域保持原样，既有完整投影仍可读取。资源重试保留已发布块，并显式拒绝实际不兼容的重新解析，以保持已存段落稳定。视觉检查点还记录处理后图片的哈希值。

原生 PDF 文本保留提取的换行和缩进。[资源 Worker](../../src/oam/workers/index_source.py)对每个无注释的物理页应用现有的接收切分限额，并在解析文本中记录页内字符偏移。只产出一个段落的页保留其页块定位，较大的页按字符范围定位。这些原生段落在已存记录和引用中均使用解析修订 2。调用方提供确切时间注释所指向的页面，继续用旧的整页扁平表示及解析修订 1，保留引用范围和注释归属。原件的字节保持原样。索引配方标识此派生过程，现有完整投影保持可读。

完整提示词能装下全部段落时，资源摘要使用全部完整段落。输入更大时，Worker 先考虑首尾段落，再逐步二分剩余的来源区间。它跳过放不下的候选，在唯一一次摘要调用前恢复来源顺序。任何省略都明确标为部分覆盖。详细段落可独立搜索，摘要归类为资源派生数据，原始证据与学习记忆仍独立管理。

[HTTPS 证据获取器](../../src/oam/resources/url_fetch.py)在保存调用方通过授权后才接收其声明的 HTML、PDF、PNG 或 JPEG 类型。系统解析公开地址，使用经检查的地址建立连接并验证 TLS 主机名，拒绝重定向和压缩，将有界的返回字节保存为不可变原件。与已提交请求相同的 URL 请求复用回执，无需再次获取。已存的可展示来源与公开错误不含 URL 查询数据，Worker 始终解析已存字节。

L1 记忆单元是可独立访问且简洁的一条事实，具有稳定的 `memory_id`。原始段落、L2 洞察各属其他类型。[HTTP 准入](../../src/oam/api/app.py)与[运行时组装](../../src/oam/api/runtime.py)通过 `/v1/retain` 接收 JSON 会话，通过 `/v1/users/{user_id}/resources` 接收文本、URL 或文件原件，通过 `/v1/users/{user_id}/profile-data` 接收结构化用户信息。调用方保存时无需管理来源或消息 ID 和修订编号。用 `PUT` 修订资源或画像数据条目时须传入 `If-Match`，[来源存储](../../src/oam/db/sources.py)分配下一个不可变修订。[索引 Worker](../../src/oam/workers/index_source.py)校验调用方确切注释的引文，在段落和有支撑的事实中发布调用方提供的时间及时间基准。未提取出事实时仍保留调用方已注释的原始证据。[公开生命周期 API](api.md)支持删除来源、按类型精准移除单条记忆或洞察。移除保留无关证据，并基于有效支撑修复受影响的派生数据。

[L1 提取](../../src/oam/indexing/extraction.py)从 [extraction-prompt.txt](../../src/oam/indexing/extraction-prompt.txt)加载通用规则，按调用路径选择打包的[分组前缀](../../src/oam/indexing/extraction-group-prefix.txt)和[参考后缀](../../src/oam/indexing/extraction-reference-suffix.txt)。通用提示词在示例之前依次给出选取标准、输出和证据要求、实体身份及时间规则。它保留显式个人事实、偏好、经历、计划、目标、决定、限制及有意义的次要背景。助手的结论、影响重大的推荐及已执行操作须有用且有依据才可纳入。泛泛解释、说明性示例和缺少具体持续背景的建议列表省略。全部合格的原始段落仍保存在 L0。紧凑模型输出省略空数组和默认事实类别，同时保留有支撑的偏好和经历类别、命名实体、关联与日期注释。单段调用省略段落 ID，按唯一提交的中心段落验证。分组调用使用本次调用内的短段落 ID。[校验](../../src/oam/indexing/grouping.py)先对照提供的归属段落检查每条确切引用，再恢复用于检查点和发布的规范段落 ID。归属缺失或无效时，仅当未改写的非空白引文在所有提交的段落正文中恰好出现一次，才恢复其归属。仅供参考的上下文、歧义匹配或与有效归属冲突的引文仍会被拒绝。恢复保留输出下标、记录 `recovered_passage` 诊断，并将提取覆盖标为部分。递归拆分的调用重建各自的标识映射。每条事实由归属段落 ID 和一段确切连续引文支撑，模型输入输出及持久事实引用均不含字符偏移。[提取校验](../../src/oam/indexing/extraction.py)要求未改写引文在归属段落中唯一出现，重复引文须扩展确切原文范围。调用方和模型生成的时间注释共享严格的四字段契约，即角色、带时区的起止时间以及确切引文。相等的界限表示有来源支撑的时间点，递增的界限表示区间，事实文本与引文保留精度、不确定性和对持续时间的表述。提取提示词规定，消息时间戳用于标识陈述时间，且只有同一事件带有显式、确定的相对日期时，才用作换算基准。对于日期不明的已完成事件和模糊的近期描述，保留事实，不在文本或注释中编造日期，也不从其他事件借用日期。今天和昨天解析为整个本地日历日，包含时区转换。默认提取角色使用 low 推理档位来区分这些情况。发布直接按起止值是否相等派生时间点或期间的 SQL 边界，附加起源以及来源消息包的参考时区，并拒绝冗余的时间标志和单条注释的来源属性输入。[既有事实参考](../../src/oam/indexing/references.py)及 L2 输入以同一四字段模型表示已存日期，存储来源与模型注释语义分别处理。[发布](../../src/oam/workers/index_source.py)将确切引文连同来源及消息身份保存，并用未改写的归属消息派生临时位置，匹配调用方提供的时间引文。跨切分边界的调用方引文关联到相交的原始段落，事实只继承完全包含的调用方引文。[上下文渲染](../../src/oam/retrieval/context.py)核对来源和消息身份，以及引文是否位于所引段落，再复用来源区块。段落定位包括来源、版本和消息标识，以及从零起算的段落下标。调用方提供的时间注释也要求确切唯一的引文，无需字符坐标。资源定位保留文档、块、页和区域身份。已完成的来源级提取检查点在输入匹配时可复用。

引用校验仅使用未改写的原文。缺失、改写、格式归一化或有歧义的引文均被拒绝。重复出现的引文须使用更长的确切原文，字符坐标和模糊修复无法替代。时间引文须在已接受的事实支撑文本中恰好出现一次。记录检查点前，递归拆分结果仍须对照原始规范段落复核。仅在某个重试子片段中唯一的引文仍须通过规范归属检查。

装填参考事实后，校验完整的序列化提取输入。如果转义或提示词开销使其超过 `extraction.max_input_tokens`，则在现有规范段落检查点内拆分提交的来源输入后再发送。每个子调用保留确切原文，并通过相同的限额及支撑校验。仅实际模型调用计入用量，无法拆分的本地输入明确失败。兼容的已成功检查点保持原样。

[切分器](../../src/oam/indexing/chunker.py)用 `chunk.ingestion` 将各消息或文档切分成互不重叠的来源段落，再执行单段或分组提取。召回的 `include.chunks` 是默认为 true 的严格布尔值，用于控制是否返回完整来源正文，接收切分边界由专用配置决定。[索引标识](../../src/oam/indexing/identity.py)包含接收切分设置，召回专用设置不参与。[能力接口](../../src/oam/api/app.py)分别报告模式上下文上限及接收设置。

[来源 Worker](../../src/oam/workers/index_source.py)发布会话事实与时间链接，再原子保存带来源、版本和 generation 的种子清单，将依赖的语义任务加入队列并让直接认领成功结算，来源操作仍在运行。链接完成前，直接事实已经可搜索。[语义处理器](../../src/oam/workers/semantic_links.py)在用户行锁之外计算有界的 ANN（近似最近邻）候选，通过短暂的受保护批次发布，再在自己的认领内完成来源就绪。合法的空种子集合可直接完成，无需 ANN。兼容重试复用已发布的事实和 embedding。[认领准入](../../migrations/0029_semantic_claim_gate.sql)遵循 `worker.claim_semantic_links`，关闭后保留语义任务且不消耗认领或尝试。在全新隔离、停止接收其他输入的导入场景中，运维人员可在全部 Worker 应用该设置，验证声明的来源、版本、generation 和提取覆盖，等待直接索引排空后再启用语义认领，直至全部链接就绪。该设置供运维控制，导入整体没有单独的持久 API。已保存的内联语义阶段可以续跑，[租约结算](../../migrations/0028_inline_semantic_lease_settlement.sql)在链接重试耗尽时保留直接记忆。启用洞察时，成功完成语义任务的来源有资格加入当前用户窗口。第一个就绪来源设定截止时间。

独立来源操作通过现有持久队列和 [Worker 运行器](../../src/oam/workers/runner.py)并发执行，受 `worker.max_tasks` 和 `user.concurrency` 限制。批量客户端可先提交有界窗口内的独立来源再等待完成，保留全部回执，等待每个操作具有必需的就绪标志后再使用整个批次。接收顺序可与完成顺序不同，可用的跨来源参考事实也可能与串行执行不同。[模型运行时](../../src/oam/models/runtime.py)分别管理生成与 embedding 预算，两者分别受部署级 PostgreSQL 许可限制。[索引事务](../../src/oam/indexing/store.py)取得[迁移 0024](../../migrations/0024_indexing_db_admission.sql)定义的独立事务咨询锁配额，跨副本上限由 `database.indexing_concurrency` 设置。本地准入限制等待共享配额之前新建的连接。提交、回滚和断开连接都会释放数据库配额，远程模型调用不占用配额。每个来源分别拥有原件、版本、认领、隔离令牌和检查点。

[分组规划器](../../src/oam/indexing/grouping.py)默认将同一来源的相邻合格段落合并为有界的 L1 调用。分组在 embedding 及并发批处理前确定，在资格不连续处断开，并保留完整段落、各自角色、消息时间戳和稳定段落归属。组大小同时受序列化输入、段落与事实项数上限及保守的输出估算约束。估算按来源文字 token 的三倍加每段 128 token，另受 `extraction.group_max_estimated_output_tokens: 4096` 限制，实际模型覆盖仍须验证。使用 Chat 和 Messages 协议时，提取和完整支撑的移除修复使用 `extraction.max_output_tokens: 64000` 作为完成预算，常规增量 L2 使用 `index.insight_max_output_tokens: 64000`，资源视觉和摘要使用 `resource.max_output_tokens: 4096`。Responses 不发送请求级输出上限，受请求时限约束。因长度终止的输出触发特定类型的溢出错误。索引流程随后递归沿段落边界对半拆分组，或在接近句末的位置拆分单段来源范围，保留确切原文和规范段落归属。拆分结果按来源顺序合并，重新映射事实关系，并汇总包括溢出尝试在内的用量。来源范围去除首尾空白后最多只有 500 个字符，或无法拆为两份非空子范围时，明确失败。各子调用在发送前重查取消和来源资格并续签带隔离令牌的租约，模型调用期间不持有事务。分支共享已有外层检查点，已完成的合并结果在重试时复用，中断或失败的拆分树可能重跑已成功的分支。过大的组沿段落边界拆分，单段使用原始提取协议。每条分组事实标出归属段落，校验针对该段落。Worker 在一次受隔离令牌约束的事务中发布整个组及跨段落关系，重试复用完成检查点。设置 `extraction.group_max_passages: 1` 恢复单段分组，标准值为 64。分组变更影响索引配方，无需重建已完成集合。

默认启用既有事实参考上下文，使用 `extraction.reference_max_facts: 10` 以及可配置的估算目标 `reference_max_input_tokens: 2048`，将事实条数设为 0 即关闭。[参考选择](../../src/oam/indexing/references.py)复用段落 embedding，对同租户、用户和 generation 下其他来源的当前合格 L1 事实排名，在提取前固定完整候选文本、身份、角色、提及日期和时间限定。[请求装填](../../src/oam/indexing/extraction.py)计入序列化元数据后，为每项候选按统一比例生成一份正文预览。最近的完整句或逗号分句边界可超出软目标，小数和数字分隔符保持原样。短文本与长文本用同一比例，且无短文本优先保留或重新分配。缩短后的文本标记 `text_truncated: true`，按不完整上下文处理，省略的限定或否定均为未知。已存完整事实和新来源证据保持原样。完整模型输入限额为硬限制，准入保留相关性顺序的前缀，只整条移除无法装入的参考记录。单段、分组和拆分重试均从冻结的完整候选派生各自视图，避免重复归一化。新事实仍须引用当前来源，独立出现的事实各自保留支撑。可选的既有关系 ID 只作已校验的诊断，既不作为支撑也不直接发布为链接。已完成提取结果复用，未完成调用移除已失去资格的参考。参考配置改变索引配方，无需重建已完成集合。质量和延迟是否因此改善仍需具备匹配条件的真实评测。

资源修订和来源删除使用[来源控制迁移](../../migrations/0009_source_controls.sql)添加的不同所有者授权。[断言用户授权迁移](../../migrations/0012_asserted_resource_grants.sql)将授权授予新增的 `dev` 及 `trusted` 用户。[后续迁移](../../migrations/0013_asserted_user_resource_grants.sql)为只有原始窄权限的既有断言用户升级，同时保留有密钥的用户及自定义授权。迁移 0014 限制注册函数的所有者与执行权限。修订提交新的当前版本、推进用户策略纪元，并在重建索引前排除上一版本。删除在同一事务中提交对全版本的排除、取消未完成来源任务，并返回独立清理操作。[资格 SQL](../../src/oam/db/eligibility.py)要求派生 L1/L2 版本的全部支撑仍为当前版本，[召回](../../src/oam/retrieval/service.py)和[检查](../../src/oam/db/inspection.py)在返回内容前重查策略。[清理 Worker](../../src/oam/governance/cleanup.py)在带隔离令牌的持久认领内移除受影响段落、事实、洞察、向量、原件字节与服务端持有的导出分片。无关的活跃来源保留资格。读取已存用户画像时，先验证当前符合条件的输入，再返回有支撑字段。

写入准入先按模式验证身份，再检查共享 HTTP 及写入容量、限制接收字节数、解析 JSON 或 multipart 并执行语义限额、核对用户和授权、执行幂等及接收容量检查，最后原子接收来源及回执。[请求中间件](../../src/oam/api/admission.py)在应用执行至响应结束期间占用一个 PostgreSQL 会话准入配额。拒绝的写入既不占总配额，也不读取正文。读取路由，包括 POST 搜索，可使用为非写入请求保留的配额。等待上传前关闭根密钥验证事务。两个写入端点均按实际接收字节执行 `api.max_request_bytes`，包括分块传输。超限时以 `413` 停止解析并关闭部分上传文件。这个编码后请求体上限独立于获准内容和原件的限额，由[标准配置](../../configs/oam.yaml)统一管理。

[事实链接构建](../../src/oam/indexing/links.py)只处理合格的新种子。直接索引发布时序链接，再原子结算 `index_source`，并在同一来源操作下调度一个依赖的 `index_semantic_links` 工作单元，使用确定性标识和不可变种子清单摘要。直接事实在 `memory_ready=true`、`temporal_links_ready=true` 和 `links_ready=false` 时已经可用。操作继续运行，公开 HTTP 状态为 `processing`，召回诊断仍为待完成。无种子的来源同样通过队列交接，语义任务认领后无需 ANN 即完成。[语义 Worker](../../src/oam/workers/semantic_links.py)在独立绑定、只读事务中每次最多读取 1,000 个种子，不持有用户行锁，也不更新投影纪元。语义邻居通过持久向量表按余弦距离升序查询，让规划器可使用现有 HNSW 索引。邻居限额前先应用当前租户与用户、generation、来源支撑资格、排除自身及既有链接容量条件。正权重和最低相似度适用于有界结果。共享支撑谓词通过确切段落、证据、来源版本及来源主键查询验证每项支撑，避免在规划器统计趋稳前重复遍历整个用户范围的父表。发布仅按种子对候选分组一次，将保留的边一次批量插入。发布使用短暂的[受保护事务](../../src/oam/indexing/store.py)，重验两端资格与每个种子的剩余限额、去重并在提交前重验租约。数据库语句超时约束语义读写，每批续签现有租约，同一认领内顺序执行各批次。`index.semantic_link_ann_iterative_scan` 和 `index.semantic_link_ann_scan_max_tuples` 管理仅限事务的索引期 ANN 调优，与召回配置独立。近似搜索的邻居可能少于限额或不同于穷举。物理索引使用及检索质量需独立验证。最终受保护结算设定 `links_ready=true`。可重试数据库故障复用同一工作单元，终态失败或[租约过期且重试耗尽](../../migrations/0023_semantic_lease_settlement.sql)保留直接记忆并报告部分失败。成功完成语义任务的就绪来源加入当前固定[洞察窗口](indexing-retrieval.md#自动整合窗口)。批量接收保留每个成员的独立来源就绪状态。

时序链接保留精确间隔、搜索跨度和确定性支撑规则。时间点构建从种子时间戳前后分别返回最多配置数量的邻居，再按确切间隔和 ID 在合并结果中取前 k 个。区间构建按范围重叠查找注释对，在单元邻居限额前为每个目标选一个规范的最佳支撑。中间投影只带种子标识及适用的向量、时间戳或注释支撑数据。发布仍在既有受保护事务内进行，要求链接阶段全部完成。链接配方参与[索引配方标识](../../src/oam/indexing/identity.py)，用户命名空间中已完成的投影继续保留。

按 ID 精确移除学习记录由[移除准入](../../src/oam/governance/removal.py)、[投影清理](../../src/oam/governance/cleanup.py)和[洞察修复](../../src/oam/governance/repair.py)负责。[版本化迁移](../../migrations/0026_memory_removal.sql)在既有操作中加入按用户及类型限定的唯一移除标识。API 准入检查 `source:delete` 并锁定用户行，再原子排除选定 ID、推进策略与投影纪元、关闭受影响的洞察与画像快照，持久保存清理和来源级整合任务。回执只保留 ID、修订和支撑元数据，修复无需旧综合文本。通过持久任务依赖确保清理先于修复，L0 原件继续保留。修复复用有界综合校验和检查点，在发布锁内重查当前支撑及直接移除标记，然后发布同一洞察 ID 的新修订，或记录有效的支撑不足。提取及常规整合核对确切 ID 的移除标记。移除会记录支撑段落 ID，清理后重试仍可跳过已处理段落。清理为较早的待移除记录补填 ID。已完成清理的更旧移除记录可能缺少防止后续重组重试的支撑数据。洞察修复不能重新打开关闭的画像快照。手动或按配置触发的自动画像刷新发布新的 L3 修订。

日常习惯学习使用现有提取和 L2 路径。[提取规则](../../src/oam/indexing/extraction-prompt.txt)将实质性内容、交互与工作流选择保留为带日期的请求观察，无需推断任务完成或形成长期偏好。[洞察输入](../../src/oam/indexing/extraction.py)从持久定位信息取得各事实的来源角色，同时携带来源引用和有支撑的日期，未知角色保留为未知。[常规整合](../../src/oam/indexing/consolidation.py)将这些来源信息交给[增量规则](../../src/oam/indexing/incremental-insight-prompt.txt)，[修复](../../src/oam/governance/repair.py)使用[完整支撑规则](../../src/oam/indexing/insight-prompt.txt)。两者采用相同的归属和时间顺序要求。现有的 `patterns` 子类型要求多次独立发生或有证据支持的趋势，保留观察期，并区分自动化和生成内容与个人行为。日常习惯无需宿主任务 ID。更新后的[索引配方](../../src/oam/indexing/identity.py)需要用户显式重建现有集合以应用变更，原有投影及排队任务保留原标签。

[接收切分器](../../src/oam/indexing/chunker.py)使用空行段落和共享的[多语言标点检测](../../src/oam/text_boundaries.py)装填无损来源范围。单次换行仍属于段内。超大单元依次按句、分句、空白和有界字符回退，只允许在硬上限内越过软目标。包括空白在内，保留确切偏移和归属范围之间零重叠的规则。索引不将纯空白片段送入外部模型。召回复用标点检测，但对可选摘录使用独立的省略策略。单段及分组溢出重试共用有界的中点切分器。边界变更推进[内容配方](../../src/oam/indexing/identity.py)，以区分新工作及此前已索引的 generation。

[洞察整合](../../src/oam/indexing/consolidation.py)在同一索引代次内交替选择向量与词法命中的已有洞察。目标查找的词法部分固定使用逐词 FTS，与公开召回排序设置独立。

## 3. 持久任务

[移除维护恢复](../../src/oam/operations/repository.py)沿用 HTTP、授权用户锁、持久任务和发布路径，无需新增队列或恢复登记。`POST /operations/{original_removal_operation_id}/recover` 需要 `source:delete`，保留原始移除回执与排除状态，只按已保存的输入和依赖重新激活失败的清理或确切记录的关联修复。清理先删除目标拥有的 `search_units` 行及其语义向量，依赖修复随后才可发布重新获得支撑的洞察修订。已完成清理和进度及兼容模型检查点保持不变，排队或运行中的任务不会重复创建。恢复将所选终态任务设置隔离令牌、补充配置的尝试预算，并原子执行现有待处理根请求准入上限。已取消、来源不合格或 generation 不合格的修复不能改换目标，未知模型结果仍需现有尝试对账权限才能恢复。过期但仍标为运行中的任务不属于只处理终态的接口范围。[API 路由](../../src/oam/api/app.py)、[运行时准入](../../src/oam/api/runtime.py)、[清理 Worker](../../src/oam/governance/cleanup.py)和[修复发布](../../src/oam/governance/repair.py)继续执行各自的归属及资格保护。

接受写入后，在返回 `202` 前提交来源或原件字节、幂等标识、根操作、封存的阶段清单及首批可运行工作单元。Worker 用短 PostgreSQL 事务认领就绪行并取得租约及单调递增隔离令牌，远程模型 I/O 在事务外执行。公开[操作重试](../../src/oam/operations/repository.py)只为失败或取消的工作单元创建关联工作，复用兼容检查点。选中单元仍有未结算外部尝试时，[HTTP 处理器](../../src/oam/api/app.py)在创建任何替代任务前返回 `409 RetryRequiresReconciliation`。

[接收计数](../../src/oam/db/queue_admission.py)在现有用户锁内统计未结束的逻辑根请求。共享洞察窗口中仍未结算的每个来源及尚有归属来源整合任务的来源都占据接收配额。自动重试沿用原有配额，显式重试重新准入。确切幂等复用和无变化的用户画像刷新无需新配额，删除清理也不受该限制。[认领函数](../../migrations/0018_profile_dependency_settlement.sql)将同一用户的计数及认领串行化，跨运行器最多允许两项有效认领。达到上限后跳过该用户，以便其他用户继续处理。

[共享模型准入](../../src/oam/capacity.py)在整个部署内将生成并发限制为 32 次、embedding 并发为八次。后台索引和前台搜索默认共享八个 embedding 许可，`provider.embedding_search_reserved` 可为搜索保留后台不可用的许可。生成和 embedding 各用独立限额。[模型客户端](../../src/oam/models/runtime.py)在远程 I/O 前提交发送意图，传递剩余时限，并在传输结果不确定时保留许可。已知完成后即可释放容量，与输出验证结果无关。运维人员可用[许可命令](../../src/oam/models/permits.py)检查并核对不确定结果，包括没有持久操作的前台调用。强制释放在远程完成可确认前保持未验证状态。[容量迁移](../../migrations/0015_shared_capacity.sql)只向运行时角色授权范围狭窄的元数据函数。

[来源仓库](../../src/oam/db/sources.py)在验证请求幂等性或分配来源、修订标识前先取得现有集合锁。文本文件的 `append` 读取当前文本，原样拼接传入的增量，无需分隔符，并在同一事务内校验最终大小，从而避免并发追加丢失内容。文档使用稳定的 `document_id`，资源 `PUT` 要求 `If-Match` 并在接收时重查，匹配的幂等重试复用此前回执。文件不支持追加。已删除的来源不可激活，普通原件读取要求版本活跃且为当前。[现用认领函数](../../migrations/0016_queue_admission.sql)无需提升队列权限即可锁定工作行，存在未解决外部结果的工作单元须经过显式[尝试对账](../../src/oam/operations/repository.py)后才可被认领。[索引 Worker](../../src/oam/workers/index_source.py)消费获准认领，持久保存兼容的模型阶段结果，并发布有支撑的表示。按用户限定的操作路由依同一授权公开就绪状态。所需证据见[核心索引与召回验收](acceptance.md#2-第-5-步-核心索引与召回验收)。

[实体发布器](../../src/oam/indexing/entities.py)分别保存按 generation 限定的稳定身份及[各自有支撑的名称行](../../migrations/0027_entity_names.sql)。现有提取调用可声明有确切来源引文的别名，或引用已提供的事实来证明同一对象被提及。名称本身不足以合并身份。名称归一化只影响查找键。原始段落、事实文本以及完整召回查询仍作为向量输入。旧字符串成员关系不会自动补上 ID，已填充的集合需要明确授权后在新 generation 中重建。

发布重查操作取消、租约及隔离令牌归属、来源版本、学习资格和 generation。独立活跃来源的直接索引可在另一来源的策略变更后继续。L2 整合的输入可能跨来源，因此还会检查冻结的策略纪元。延迟或已过期的 Worker 可保留尝试诊断证据，但无权发布权威结果。重试复用兼容的已完成任务，只为未完成且仍合格的阶段创建新尝试。

已完成的模型响应保留经独立验证的用量，即使生成被截断、拒答、返回空内容，或 embedding 或评分无效。[模型适配器](../../src/oam/models/runtime.py)将用量传至[既有尝试失败路径](../../src/oam/indexing/store.py)，不会捏造不可用或格式错误的用量。可重试的提取或洞察 JSON 格式、模式错误使用剩余持久认领预算。在同一事务内结算失败尝试并重新排队，下次认领复用已完成阶段的检查点。未拒答且已完成的模型响应，若明确返回 null、空字符串或全空白内容，且无推理或工具调用输出，也使用剩余索引认领预算。显式 `no_facts` 不经重试即成功，语义链接重试策略延续。其他模型适配器输出拒绝及输入或输出超限不会单因用量已知而重试。无响应的网络超时维持未解决状态，且不自动重放。同一来源修订和 generation 的成功阶段与用量已知的失败尝试各计一次 token，重试耗尽明确报告部分失败。

## 4. 检索与用户画像

[词法读取](../../src/oam/retrieval/repository.py)复用索引时保存的、带来源支撑的实体名称及别名。通过索引查找完整查询中归一化后的完整名称，并验证当前支撑。已识别名称的词在候选和主词列表中排到现有查询词限制之前。与任一匹配身份关联的合格事实可得到最多为 `search.query_entity_boost` 的比例加权。仍优先匹配完整查询及主词，仅实体匹配在正排名匹配之后补充剩余容量。同名实体仍是不同候选身份。两种词法排名方式都贡献同一条词法通道，查询时无需提取实体或调用模型。向量输入仍使用完整的原始查询。这些事实以独立的实体匹配提示通过部分匹配筛选，保留严格词法匹配元数据及必需的来源支撑。相关联的召回日志和 `diagnostics.local_context` 记录配置的加权和命中事实数。加权设为零可跳过名称查找并保留普通词法选择，无需重新索引。

Embedding 绑定支持可选的 `query_prefix`，默认为空。[召回查询编码](../../src/oam/retrieval/service.py)仅在完整原始查询前添加一次前缀。词法检索、时间推断及呈现给回答模型的查询文字保留原始输入。[文档 embedding](../../src/oam/models/runtime.py)继续沿用原格式。查询格式变更影响实际运行配置标识，现有文档索引继续有效。

[已存名称查找索引](../../migrations/0030_entity_empty_lexical_names.sql)覆盖全文向量为空的名称按空白分隔的第一个部分，使停用词不会隐藏有支撑的多词名称或别名。启动更新后的服务前应用模式迁移。该索引覆盖已有数据，无需重复提取或 embedding。获取候选记录前先合并词法和实体身份的候选 ID，两类查找可各自使用索引。

[来源原文读取](../../src/oam/retrieval/repository.py)在有界会话事实种子或原文发现种子的确切来源版本内，按完整查询向量对符合条件的用户段落排名。先收集这些版本的合格单元 ID 及 embedding，再按精确余弦距离、稳定的单元 ID 同分规则和现有候选上限处理。全局近似邻居扫描预算不截断此选定来源池，请求时限仍适用。需要完整正文时，两种种子均可恢复独立相关、且没有已提取事实的用户原文，禁用段落时跳过该原文发现查询。[召回组装](../../src/oam/retrieval/service.py)先收集已排名的原文和来源支撑，再决定最终纳入。[上下文选择器](../../src/oam/retrieval/context.py)按最终相关性在一个完整渲染限额内考察合格的学习和原文根条目，Fast、Normal、Deep 分别默认 8,000、16,000 和 24,000 token。无提取事实或学习证据组装不下时，独立原文仍可参与。学习根条目需要完整而合格的支撑，包括必需事实、引用及默认纳入的完整原文。`include.chunks: false` 省略所有完整来源正文条目和区块，同时保留学习支撑及真实引用引文。两种表示都校验来源资格。完整的暂选渲染包含全部元数据且须适配预算，重复段落只计一次，过大的证据组整体跳过且不裁剪。只有一条合格 L1 事实时同样受渲染上下文上限约束。跳过超大证据组后仍可纳入后续较小组。每个唯一学习条目和完整原文各占所属 `max_results` 结果池的一个配额。来源发现和补充恢复无额外融合贡献。运行时计数元数据标明估算器，调用方独立使用实际回答模型精确计数。

[向量读取](../../src/oam/retrieval/repository.py)为用户范围内的精确检索池按余弦距离排序，再按稳定的单元 ID 确定同分顺序，最后应用候选上限。规模小的 Fast 请求保留近似 HNSW 查询形态。

三种模式在判断来源资格并组装完整支撑后应用配置的[局部证据筛选](../../src/oam/retrieval/local_context.py)。现有内容加载查询同时确定符合条件的直接向量用户事实，用作支撑见证。直接向量、严格词法或字面及配置的图命中保有独立资格。有界词法通道直接召回的用户原文无需单独命中事实。该通道中第一个已加载且合格的记忆原文，只要具有已存用户或助手角色也可纳入，包括从助手发言开始的历史。第一个用户原文会占用这次回退机会，较弱的助手原文仍须满足现有独立资格或局部证据要求。这些豁免保留相关性顺序与上下文限制，不提供见证或来源扩展权限。其他 L0/L1 会话根条目须引用同一来源版本中具有见证的用户消息，或紧接该消息的助手回复。间接命中的助手原文还需要对应用户原文的确切来源、版本和段落，并要求引用该原文的用户事实也在 `source_seed_results` 限定的同一原始向量前缀内。系统逐条匹配引用，然后推导其回复位置。学习事实仍按现有规则决定资格，必需原文即使作为独立根条目时被排除，仍可随合格事实进入上下文。这里使用原始前缀，来源发现则使用融合或多样化后的种子顺序。启用筛选时，补充发现只使用独立命中且有用户证据支撑的事实所对应的确切来源版本。在现有全局来源种子上限内，这些来源中最接近查询的用户原文成为不可继续传播的上下文，归属于对应排名最高的独立用户事实。它们紧随该事实的完整支撑参加竞争，若未纳入归属事实，则回退到靠后的普通候选位置。这些恢复的原文不能作为向量或独立见证，也不授权纳入助手回复或继续发现。该机制优先保护有来源支撑的用户细节，可能挤出靠后根条目，因此须同时测量覆盖和无关上下文。全程无需调用模型评分。资源、洞察及已保留根条目的必需支撑沿用原有规则。[上下文选择器](../../src/oam/retrieval/context.py)随后可在普通事实入选后立即尝试纳入已经发现的相邻用户原文，使用当前来源定位及合格原文候选与来源段落的并集。必需支撑优先纳入并保持完整。可选邻居每段使用 `search.adjacent_user_context_max_chars` 个 Unicode 字符（默认 1,000），保留上一用户段的尾部和下一用户段的头部。边界选择器先尝试 Unicode 句末符，再尝试分句标点。它保留闭合引号，排除数字和缩写中的点，并跳过找不到边界的片段。普通段落边缘不能当作句界，只有编号为零的段落代表已知消息起点。裁剪后的文字含段内字符偏移及可见摘录标记。完整原文优于同标识摘录，升级时核查完整渲染预算。来源窗口回退不能绕过该上限，过大的可选摘录会省略，较高排名原文保持原位置。禁用段落时跳过这些可选正文，仅供洞察支撑的段落不会引入相邻轮次。三种模式均通过 `search.adjacent_user_context` 默认启用相邻用户上下文。共享的 `search.partial_match_gate` 默认为 `user_fact_exchange`，三种模式均接受 `"off"`。诊断和关联日志记录筛选结果、被筛选的根条目、选中的窗口原文及耗时。

即使直接检索已找到带日期的证据，[时间阶段](../../src/oam/retrieval/service.py)也会在请求窗口内独立搜索与查询相关、符合条件的事实池。系统将这些候选与合格的向量根条目合并，再执行原有的有界分桶、种子选取和扩散。所选根条目与新发现共用同一个时间通道，并按普通规则复核时间见证。每个广度优先前沿执行一次同步邻居读取。对每个父节点，两个时序方向及任何启用的出向因果链接先应用来源和目标资格、语义门槛、时间见证和可选边 ID 检查，再通过现有边索引选择排名最高的合格邻居。它们的并集沿用每父节点按权重、目标 ID 和边 ID 排序及限额，避免扫描整个前沿，同时只纳入已经校验的边。到期时丢弃尚未完成的前沿。通道上限、语义门槛、根节点、总节点及邻居上限和绝对时限共用。显式时间基准彼此独立，消息时间戳不能代替缺失的事件注释。

三种模式默认使用 `search.lexical_ranking: whole_query`，对词之间用 OR 连接的全文匹配列表排名。`per_term` 为不同的词分别排名并融合有界列表。whole_query 在 Normal 和 Deep 应用覆盖密度的文档长度归一化，per_term 在三种模式中均应用。两者都优先完整查询匹配和主词合取，在候选上限前验证来源支撑，并贡献一票词法融合权重。[词法读取](../../src/oam/retrieval/repository.py)

[召回服务](../../src/oam/retrieval/service.py)与[资格 SQL 仓库](../../src/oam/retrieval/repository.py)实现一条非生成式 Fast、Normal、Deep 流水线。显式排名窗口优先，否则由[查询时确定性解析](../../src/oam/retrieval/query_time.py)从受支持日期表达或明确两端点的绝对日历区间解析一个事件时间窗口。日历区间包含末尾的日、月或年，分别将两个本地边界转为 UTC。显式窗口仍优先，推断的时间基准保持为事件，完整原始查询原样向量化。隐式日期不明确、无效或不受支持时，仅关闭时间通道并报告诊断，正常处理请求。FTS 与严格字面匹配组成一条去重、有共享上限的词法排名列表，各单元只贡献一票融合权重。直接时间种子复用同一列表。三种模式均融合向量、词法和可选时间通道。图配置可加入常规图通道。显式启用的[个人证据通道](../../configs/README_CN.md#8-个人证据候选)增加由当前偏好及经历支撑的合格用户原文列表。普通图检索不排除日期，时间扩散的种子、邻居和路径见证严格符合时间基准及窗口。租户、用户、当前来源版本和记录支撑资格始终为硬约束，[核心验收](acceptance.md#2-第-5-步-核心索引与召回验收)仍要求完整 HTTP 和评测矩阵。

各[就绪检查](../../src/oam/retrieval/repository.py)在其 SQL 语句中只选择一次操作 ID，再统一为每个活跃来源版本选择最新的非整合操作。待处理及部分覆盖继续反映当前基本索引工作。召回在加载上下文前重新检查来源和解析，在返回内容前最终核查策略纪元。

[词法配方](../../src/oam/retrieval/fts.py)将英文单词交给 PostgreSQL `english`，将数字和固定版本的 Jieba 搜索词交给 `simple`，保留受保护的否定词和时间词。[HTML 解析](../../src/oam/resources/html.py)将可用页面标题、章节标题及表格说明用于 A/B/C 排名权重，段落文本使用 D，其他现行来源只提供 D。召回用 OR 组合不同的内容词。默认以所有者局部 BM25 分数加两倍覆盖密度分数，对普通全文命中排名。三种模式均在通道最终限额前保留主词及完整匹配优先和当前来源资格。两个分数均使用配置的字段权重，相关性同分时按新近度，再按稳定单元 ID 排序。精确锚点结果使用相同的双语表示对查询中的其他单词排位。[模式迁移](../../migrations/0008_bilingual_fts.sql)增加独立的双语 GIN 向量索引，并保留原有词法向量供旧副本读取。旧投影保留可读性，需要重建才能添加双语向量。

各模式使用自己的配置时限及包含种子的独立时间遍历预算。`search.fast.temporal_nodes`、`search.normal.temporal_nodes` 和 `search.deep.temporal_nodes` 分别默认 64、200 和 300，不受最终结果上限影响。Fast、Normal 和 Deep 都是可配置的预设。每次请求的 `overrides` 在配置校验后覆盖允许的预设字段，或共享词法排名、部分匹配筛选、相邻上下文、因果遍历和来源正文策略，并通过直接、批量和规划召回传至检索与上下文组装。[模式配置](../../configs/oam.yaml)分别管理 `search.fast.entity_semantic_graph`、`search.normal.entity_semantic_graph` 及 `search.deep.entity_semantic_graph`，默认 `"off"`、`light`、`light`。Off 跳过实体和语义图扩展，light 通过共享的已存实体 ID（含有支撑的别名）扩展，full 再加入已存语义链接。共享布尔值 `search.causal_graph` 控制出向两跳因果遍历，以及时间搜索的因果边。默认为 false，时序链接和日期过滤继续生效。[仓库](../../src/oam/retrieval/repository.py)在候选上限前省略已禁用的实体及别名、语义和因果 SQL 分支，纯因果检索仍使用有界的向量种子。两类图组件共用图融合通道和现有上限。三种模式在各自的限额、时限和上下文预算内均支持三种图选项。[配置模型](../../src/oam/config.py)拒绝无效选项及已删除的全局 `search.fast_graph` 键。Fast 专用请求字段 `fast_graph` 省略或为 null 时继承 `search.fast.entity_semantic_graph`，显式 true 选择 light，false 选择 off，与 causal_graph 独立。[直接、批量和规划召回处理器](../../src/oam/api/search.py)都会保留该覆盖。诊断和轨迹记录选中的 `entity_semantic_graph` 与 `causal_graph` 值、执行阶段、降级及用时，关联执行日志记录路径和结果。图扩展共享合格事实的支撑证明，只校验与合格种子关联的实体名称支撑，并在成员限额前保留来自非种子事实的规范名称及别名证据。Fast 始终跳过模型重排，Normal 和 Deep 可在组装上下文前通过配置的重排器对融合后的候选文本打分。召回 SQL 只在读事务内禁用 JIT 并选择自定义计划，让池化连接按当前租户和用户基数规划，而非复用另一范围的通用估算。支持管道的数据库客户端依序一起发送每条语句的超时设置及查询，并在读取结果或释放所属事务前排空结果。无管道支持时保留串行执行。Normal 和 Deep 使用自己配置的图选择，在有绑定时进行重排。终点实体、单跳语义和第二跳因果候选在各自限额前排除所有图种子，身份支撑和因果第一跳中间种子仍可用。三种模式均可通过直接向量或词法搜索返回 L2 洞察。标准 Normal 和 Deep 配置的图通道权重为 0.1，其他已执行通道为 1.0，Fast 的已执行通道等权。Fast 默认最多三种通道，启用图时最多四种，Normal 和 Deep 最多四种。Normal 和 Deep 共用[配置的通道权重](../../configs/oam.yaml)，运维人员可覆盖完整权重映射或其中单项。向量和图共同命中时获得两票融合贡献，最终只返回一项并保留路径证据。最终[上下文准入](../../src/oam/retrieval/service.py)按融合或配置重排的相关性对各类证据排序，多样性只影响有界原文发现。相关事实 SQL 先对合格候选排序，再取有界结果。最终准入前收集相关事实、普通来源窗口段落及支撑条目，完整渲染须满足模式总预算及各池结果上限。[图激活](../../src/oam/retrieval/algorithms.py)用 `n * n / (n * n + 1)` 计算 `n` 个不同共享实体的贡献，并加上最强语义和因果链接，以此排列该通道。[词法检索](../../src/oam/retrieval/repository.py)按配置使用整句排名，或把有界的逐词排名列表组合成一条词法通道。过滤后没有有信息量的词时，两者都使用严格的全文匹配。确切引号短语和带连字符的编号使用有界字面匹配，其余查询词在限额前给这些精确结果排名，普通连字符词仍可部分 FTS。没有重排绑定时，Normal 和 Deep 直接使用融合结果，无需降级。三种模式共享引用加载、`search.fact_source_bodies` 策略和运行时估算器下的完整上下文准入，配置的来源发现上限均为 36。每种模式只有一个渲染上下文上限，学习文本和原文共用预算。外部评测用各自的 tokenizer 独立统计实际传给回答模型的上下文。记忆和证据按相关性竞争，没有来源类别配额，学习条目与完整原文仍分别限制条数。[核心验收](acceptance.md#2-第-5-步-核心索引与召回验收)要求在关闭画像时、L3 实现前通测三种模式。

普通实体扩展关联已存 ID，并用同一合格事实投影重验成员关系和当前名称支撑。先校验种子，再取得未加限额的可达事实超集。可达路径包括已存身份及其名称支撑锚点、启用因果检索时的出向两跳因果，以及 full 时的双向语义链接。所有这些候选均先完整复核当前支撑，再应用排名和分支限额，无关历史无需逐事实验证。Light 在读身份前保留其完整历史的非种子资格检查，各图选择在给额外候选排名时都排除种子 ID。成员限额前验证可达身份集合内的全部有据名称，包括来自非种子事实的别名锚点。实体、因果和语义图均遍历事实，直接词法和向量检索对段落及洞察仍分别验证资格。路径保留选定的别名引文和来源定位作为元数据，并计入完整渲染上下文。身份支撑已撤销或无法装入时，移除依赖它的图贡献，单独入选的直接事实仍保留资格。Fast 查询时不调用实体解析器。`entity_semantic_graph` 为 `"off"` 时跳过实体与别名及语义扩展，独立启用的因果遍历仍可贡献。Light 和 full 复用已存身份支撑，所有启用的图组件共用一票融合贡献。已存语义邻居使用索引链接，实体排名在各自倒排列表内用查询向量距离，实际相对开销取决于扇出和支撑检查。

Fast 的 light 扩展先查限定范围的原始事实超集有无非种子项。无非种子项就证明既有完整历史资格门为空，有非种子项则照常执行完整图查询。没有显式或推断时间窗口的严格 Fast 请求，在 embedding 和文本检索完成后共用一个 READ COMMITTED SQL 阶段。部分、带时间及扩展模式请求继续使用独立读事务。成功加载的段落只在当前请求内复用，缺失的来源窗口明细按原有顺序查询。受保护的轨迹发布在剩余时限内核对当前活跃用户与策略纪元，提交后才返回响应。向量 ANN 控制复用候选检索前现有的时限设置语句。支持管道传输时，准入的超时设置和查询一同发送，保持事务与会话锁的生命周期。

入选洞察要求已记录的所有 L1 支撑修订，以及这些事实直接引用的合格原始段落。[召回仓库](../../src/oam/retrieval/repository.py)在既有伴随项上限内解析支撑。若上限无法覆盖每个记录的支撑，就省略洞察并报告限额原因。 [来源选择器](../../src/oam/retrieval/context.py)为洞察解析确切引用，不扩展相邻轮次，普通 L1 窗口保留有界的相邻用户轮次发现。每条洞察与其必需事实和引用构成完整组，只有 `include.chunks` 为 true 时才纳入完整原文正文。组继承根条目的相关性位置，并在完整渲染上限及各结果池条数限制内原子准入。超限的洞察同样省略。查找和加载失败遵循现有召回失败契约。返回前重查最终洞察修订资格，无需在读时增加持久重试或模型调用。

上下文渲染器使用局部条目和来源引用，同时让结构化条目保留完整溯源信息。只有完整且非空的时间证据列表一致时，分组事实才继承原始段落的时间。准入对每个完整暂选渲染计数，包括输出元数据及分隔符。若使用同一估算器得出的值更小，仍可使用完整 ID 格式。

条数和 token 准入之后，[共享上下文渲染](../../src/oam/retrieval/context.py)只在来源、版本、消息、角色和段落身份全部匹配，且各确切支撑引文在该段落中唯一出现时，才将事实关联到已选原始段落。返回条目保留相关性顺序、归一化事实文本、完整引用、事实自身时间注释及图路径。上下文在组内最早的成员排名处展示一份原始段落，再展示相关事实区块。紧凑区块用 `source=[n]` 指向选中的原文条目，完整 ID 回退格式用 `Source: [passage_id]`。其他会话引用保留来源修订、说话者、消息 ID 和确切引文，未知引用结构保留完整 JSON。仅当事实完整且非空的时间证据与已选原文匹配时使用 `time=source`，否则保留可见的独立时间字段。带额外日期或图路径的事实保留其结构化记录。洞察、来自不同独立出处的条目及无法由一份已选段落完整支撑的事实保留独立区块。分组没有额外的模型调用或数据查询。对最终渲染按模式限额重新计数，并固定元数据键顺序，供[记录回放](../../src/oam/debug/traces.py)使用同一渲染器。

PDF 页只提取部分内容时，需要显式设置 `allow_partial: true`。默认召回在返回上下文前拒绝该不完整资源。[第 6 步验收](acceptance.md#3-第-6-步-证据与联合召回验收)通过公开 HTTP 验证双语原件、物理页引用、部分 PDF 行为和记忆与证据联合上下文。

[标准配置](../../configs/oam.yaml)统一管理三种预设及其时限。公开的 `POST /v1/recall` 要求 `user_id` 与 `query`。请求省略 `recall_level` 时采用运维设置的 `search.default_recall_level`，标准值为 `fast`，请求显式指定的模式优先。内置 Inspector 和随 v0.2.1 提供的接入归档默认显式发送 Fast。每次 Agent 调用前召回或 ReAct 召回都有各自的操作预算，受调用方显式给出的更短时限约束。可信共享轮次准入是内部可选限制，公开请求体不接收该字段。系统不会自动提升模式。成功召回在最终策略检查后，将被考虑的有界通道与最终上下文记录在同一轨迹 ID 下。[记录轨迹读取器](../../src/oam/debug/traces.py)公开内容前根据当前资格核验每个已存候选。

[批量和规划召回](../../src/oam/api/search.py)经[授权 HTTP 运行时](../../src/oam/api/runtime.py)复用[直接召回服务](../../src/oam/retrieval/service.py)。批量在发送前验证调用方的每个查询、为子查询按确定性规则分配所选模式的总预算份额，并继承相同的段落布尔值。它在同一个绝对时限内按配置的并发上限执行查询，按输入顺序返回各自结果。规划召回首先至多调用一次配置的[规划器模型角色](../../src/oam/models/runtime.py)，验证其有界查询列表，再在剩余时限内执行。规划失败或无效时，若仍有时间则用调用方的原始查询。[请求契约](../../src/oam/contracts/search.py)让两条路径共用模式及可选时间控制。普通直接和批量召回维持非生成式。

宿主在调用 Agent 前执行 Fast 召回，将其证据提供为初始上下文。在推理和工具调用交替进行的 ReAct 循环中，Agent 可再次请求 Fast、Normal 或 Deep。OAM 执行选定预设，Agent 决定后续查询、模式及最终答案。

[OpenClaw 适配器](../../integrations/openclaw/index.ts)将选定的一个 OpenClaw Agent（默认 `main`）绑定给一个配置的 OAM 用户。经所有者授权的本地 WebChat 路由覆盖该 Agent 的会话，外部频道须有获准的直接对话身份。适配器在获准轮次之前通过 OAM 召回，结束后保存已完成的人类消息。[插件设置及路由限制](../../integrations/openclaw/README_CN.md)介绍运维配置。

可选的 [cron 捕获](../../integrations/openclaw/cron.ts)为选定 Agent 保留具有明确所有权的周期性用户任务定义，排除心跳负载、工作流提示词、可执行负载及传输配置。停用和移除例行任务仍是有意义的历史，一次性、进程或流任务定义不会被记作长期习惯。周期任务的 `ok`、`error` 和 `skipped` 结果可成为符合条件的用户角色观察，包含任务 ID、状态及结构化运行时间。生成的助手报告、原始错误和交付诊断不纳入。日志用任务、操作、来源和时长关联已接收请求，并说明筛选决定。宿主取消时停止对账。适配器不控制调度器，也没有数据库读取、历史对话补录或本地交付队列。

[画像输入加载器](../../src/oam/profiles/inputs.py)选取当前由会话支撑的 L1 事实及 L2 洞察，连同所引 L0 段落和活跃结构化画像数据。合格的 L1、L2 记录均参与判断生成输入变化。资源及不合格的助手文本不能支撑画像。来源事件时间让生成文字可带上所述年龄及既往事件的时间限定。[注册的画像数据映射](../../src/oam/profiles/resources.py)在来源激活前验证确切值。[画像服务](../../src/oam/profiles/service.py)无需模型调用即可比较合格输入、标准生成提示词和已存指令的标识。`GET /profile` 根据合格来源验证支撑后，读取一份已存正文、引用、上次发布时间和处理元数据。配置的模型或索引配方变化后，仍可读取符合条件的已存画像。刷新使用已存用户命名空间。`POST /profile/refresh` 无变化时返回 `200`，有变化时返回持久化 `202` 回执。先提前执行待处理来源的延迟 L2 任务并等待，再生成画像。受限的输入选择器会报告未提交生成的合格条目数，对应修订不会标为完全最新。刷新支持全量及增量模式，默认增量。[增量编辑器](../../src/oam/profiles/delta.py)保留未改动的带引用区块，并用新审查证据验证编辑。持久的哈希输入清单识别新增、变更与撤回的证据。先前被省略且内容未变的证据仍未覆盖，直至执行全量重建。基线不兼容或缺少支撑时回退至全量重建，发布时重验基线和证据。[标准画像提示词](../../src/oam/profiles/prompt.txt)为简洁的当前画像选择有用支撑，以最终状态替换已明确解决的更正，保留重要且未解决的限定和带日期的年龄，省略临时测试标识及偶然任务细节。历史背景及宽泛项目活动仅在有用时简略纳入。[画像 Worker](../../src/oam/profiles/worker.py)以 JSON 传输外层生成一份有界文本产物，验证其引用支撑，将确切画像数据值和可读 References 附加到默认 Markdown，去除默认格式下源相同的重复引用且保持所引来源，拒绝无法解析的引用编号，并在发布前重查输入、租约和隔离令牌。活跃来源版本与 generation 下成功的洞察任务可使画像输入就绪，包括已成功的重试，即使原回执仍保留失败诊断。同一来源、版本、generation 中每项未解决的移除修复仍是独立义务。较新的成功修复不能掩盖其他待处理或终态失败的修复。完成受影响修复会清除对应覆盖要求，维护恢复不改变操作创建顺序。经授权的自定义指令可要求其他文本格式，包括 JSON。已存指令参与判断刷新输入是否变化，后续指令或重置会取消冲突的活跃画像工作。取消阻断发布。已经完成的尝试即使被取消仍会结算，因此可以重新请求同一指令，外部结果不确定时仍须对账。所引用支撑撤回或被替代时，整份自由格式快照暂停返回，直至刷新。新增合格输入时，先前仍合格的文档可用，并标记为非最新。可选的[画像调度设置](profiles.md)通过现有持久 Worker 准入自动刷新。关闭自动触发时，L2 变化不生成 L3，仅证据变化不影响画像标识。自定义生成通过独立 API 返回带引用的临时结果。召回直接调用[检索服务](../../src/oam/retrieval/service.py)，只返回查询相关记忆和证据，独占全部请求预算，无需读取已存画像或为其预留 token。应用可通过 `GET /profile` 独立读取画像文档，再按需与召回组装。画像读取和导出单独加载符合条件的已存支撑引用，独立于 L1/L2 生成输入。[文档渲染器](../../src/oam/profiles/document.py)读取旧版按字段组织的修订，无需重新生成或持久化。它保留已存值、限定、冲突及全部合格引用，支撑无法解析时暂停返回整份文档。画像读取有独立的整文档预算，且返回前重查来源策略。召回从不读取、返回或刷新 L3，既支撑画像又与查询相关且有来源的 L1/L2 事实仍可召回。批量和规划请求沿用同一纯检索路径，并遵循共享的预算、授权和时限规则。两个独立端点各自校验来源策略，不保证两个响应构成同一原子快照。

[DSH 适配器](../../integrations/dsh/index.mjs)从所有者所选的个人配置出发使用同一公开 HTTP 契约。它为人类轮次召回，只在轮次结束后捕获人类文本，排除子智能体，并公开显式的 `memory_search` 与按 ID 移除的 `memory_remove`。对配置用户，每次移除只针对一条记忆或洞察，并将排除回执与存储清理分开校验。调用移除工具的已完成轮次保留人类证据，但关闭学习。返回的完整上下文须适配配置的 token 上限，超限结果整份省略。周期任务路径保存定义、变更、移除及最新确认交付，排除提示词和生成输出。两个适配器均可从带版本的本地 tarball 安装。

## 5. 检查与可移植导出

读取学习记忆依次通过 [HTTP 路由](../../src/oam/api/app.py)、[运行时授权](../../src/oam/api/runtime.py)、[来源检查](../../src/oam/db/inspection.py)和共享的[资格 SQL](../../src/oam/db/eligibility.py)。公开的 `memory_type` 选择 `basic`（L1 事实、偏好及经历）或 `insight`（L2）。列表可省略该字段，读取单条学习记录详情时必传。[记忆契约](../../src/oam/contracts/memory.py)将公开名称一次映射至内部类型，响应公开该类型，同时保留 Inspector 使用的既有内部 kind 字段。列表先按选定类型筛选再分页，在同一语句中计数并选择有界页面，按创建时间和单元 ID 排序，只为选中的记录附加溯源信息。类型化详情用规范 L1/L2 标识，沿用同一资格验证及引用组装。两者在返回前都重查策略纪元。偏移与游标分页读取当前集合，需要固定集合时可使用快照导出。L3 以独立的已存画像读取提供，无需触发生成。

检查仅读取当前合格的 L1/L2 单元、资源和画像数据。[来源检查](../../src/oam/db/inspection.py)在用户读取授权下列出活跃文档及画像数据、引用的记忆、当前原件、证据摘要或确切画像映射，以及操作就绪状态。打包的 [Inspector 客户端](../../src/oam/web/app.js)使用这些公开路由，浏览器不能覆盖服务端策略。来源和生成内容皆作为纯文本载入，凭据仅留在页面内存，API 在 CSP 下提供同源静态资源。Inspector 展示唯一一份已存用户画像文档，安全格式化可解析的 JSON，经公开路由提交显式刷新指令。[画像读取服务](../../src/oam/profiles/service.py)也从[打包源文件](../../src/oam/profiles/prompt.txt)返回当前生成提示词。Inspector 在默认收起的面板内将其显示为只读文本，并标明是否由已存自定义指令补充。

已存解释、输出差异及只读回放使用[轨迹策略验证](../../src/oam/debug/traces.py)，防止轨迹重新披露已过期或已撤回的候选。[可移植导出](../../src/oam/exports/repository.py)记录 format-1 清单，包含当前来源标识、L0 证据及段落、有支撑的 L1/L2 记录及其链接、资源摘要、合格用户画像内容及引用元数据、原件描述符。[有界 JSONL 分片](../../migrations/0010_export_parts.sql)只保存记录且不复制原件，下载原件时复核当前来源版本、校验和与策略。每次提交索引事务都会推进[投影纪元](../../migrations/0011_projection_epoch.sql)，因此即使是进行中工作的部分发布，也会使先前导出失效。接收来源及策略变化同样要求重新导出。[离线验证器](../../src/oam/exports/validation.py)核对下载成员的路径、数量、长度、哈希、来源及原件标识和支撑关系。OAM 的删除控制不适用于已下载副本。

## 6. 运行拓扑

[API 生命周期](../../src/oam/api/app.py)默认在检查配置与数据库权限后启动[共享 Worker 运行器](../../src/oam/workers/runner.py)。专用线程池执行同步处理器，不占用 HTTP 处理线程。独立部署在 API 进程关闭 `worker.embedded_enabled`，另行启动 `oam worker`。`--once` 仍只认领至多一个工作单元。每个运行器最多有 `worker.max_tasks` 个任务配额，默认十个，部署工具选择进程数。API 与 Worker 客户端保有各自的数据库角色及前台与后台准入标识。

关闭时先停止新认领和模型发送，再等待至多 `lease.shutdown_seconds`。未完全排空会被报告，仍运行的同步任务继续持有其客户端，直到最后一个任务退出。服务无法强制取消任意 Python 线程。就绪状态提供嵌入式运行器健康和模型许可未知状态导致的饱和情况，完整发布仍有独立验收。PostgreSQL 高可用及进程突然丢失分别另行验收。
